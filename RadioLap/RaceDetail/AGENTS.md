# 레이스 상세 작업 안내

## 문서 진입점

[README](README.md)의 목적을 먼저 확인하고, [Repository 계약](Docs/RepositoryContract.md) → [UseCase 계약](Docs/UseCaseContract.md) → [화면 상태와 동작](Docs/PresentationState.md) → [완료기준](Docs/CompletionCriteria.md) 순서로 검토합니다. 목적·설계·완료기준·테스트·구현 순서로 작업하며 기존 코드나 테스트 기대값을 요구사항의 근거로 삼지 않습니다.

## 현재 작업 범위와 상태

목록에서 선택한 Race와 검증된 season을 전달받아 기본 정보를 보존하고, sessionID로 참가자·결과만 조회하도록 모델·Provider·Interactor·ViewModel·화면과 관련 테스트를 구현했습니다. 목록에서 상세로 진입하고 드라이버 선택 후 임시 이동 확인 화면으로 이어집니다. 실제 라디오 기능은 포함하지 않습니다. 현재 앱에 연결한 상세 데모 자료는 싱가포르 세션(11388)뿐이며, 다른 레이스는 자료 부재로 조회 실패를 표시합니다.

화면 연결 후 앱 빌드와 목록·상세 테스트 85개가 통과했습니다. 이후 드라이버 이동 대상의 동등성·해시 계산을 sessionID와 driverNumber만 사용하도록 수정했으며, 이 수정 후 빌드·테스트는 재실행하지 않았습니다.

기존 캡처와 HTML 소스를 기준으로 화면을 구성했습니다. 시뮬레이터에서는 기본 정보·22명 참가자·순위 없는 하단 그룹·순위가 있는 미완주 표시, 드라이버 선택·상세 복귀와 상세 스크롤 위치 유지, 실패 안내·재시도·목록 복귀를 확인했습니다. 목록 복귀 시 스크롤 위치 보존과 빈 참가자·취소·결과 미제공 상태의 직접 화면 검증은 남아 있습니다. HTML의 브라우저 상호작용은 확인하지 않았습니다.

현재는 순차 커밋 준비 단계이며 아직 커밋하지 않았습니다. 기존 미커밋 변경을 보존하고 출처나 기여를 추정하지 않습니다. 위 검증 결과를 모든 완료기준의 충족으로 해석하지 않습니다.

## 범위와 제약

- 목록 문서 변경은 검증된 시즌을 Race.season에 보존하고 선택한 Race를 상세에 전달하는 경계로 한정합니다. 목록의 기존 선별·정제·정렬 정책은 유지합니다. Race 파일 이동과 공통 모델 계층 신설은 포함하지 않습니다.
- 목록 복귀 시 재조회하지 않고 기존 목록과 보던 위치를 유지하는 합의를 따릅니다. 정책 합의와 실제 스크롤 보존 검증은 구분합니다.
- 라디오 조회·재생·대사 생성, 공개 라디오 개수 표시, 실제 API Provider 구현은 포함하지 않습니다. 라디오 화면에는 이동에 필요한 식별자 계약만 정의합니다.
- 와이어프레임의 검토용 버튼, 특정 경기 선택 제한, 선수·번호·인원수·순위·날짜는 제품 요구사항으로 고정하지 않습니다. 사진·팀 색상·랩·타이어·주행 중 순위를 상세 범위에 추가하지 않습니다.
- 상세 Repository는 참가자·결과 자료만 읽으며 목록의 세션·대회 Fixtures를 다시 읽지 않습니다. 입력 자료의 표본 값으로 상세 계약의 범위를 확대·축소하지 않습니다.
- 문서 추가·이동·삭제 시 앱 타깃의 문서 제외 설정을 맞춥니다. 구현·검증 설명 문서는 별도로 만들지 않고 소스·테스트 디렉토리로 연결합니다.

## 공통 규칙과 작업 순서

[아키텍처](../../docs/ARCHITECTURE.md), [코딩](../../docs/CODING_CONVENTIONS.md), [문서화](../../docs/DOCUMENTATION.md), [테스트](../../docs/TESTING.md), [커밋](../../docs/COMMIT_CONVENTIONS.md) 규칙을 따릅니다. 화면 검토 시 [와이어프레임 안내](../../docs/WIREFRAMES.md)를 읽고 [HTML](../../docs/radio-lap.html)을 직접 확인합니다. 제공된 캡처 검토와 HTML 상호작용 확인을 구분합니다.

책임·입출력 합의 후 완료기준과 공개 인터페이스를 정리하고 테스트·구현 순서로 진행합니다. JSON 자료는 수정 없이 사용할 입력으로 구성하고 재사용 가능한 자료는 합쳐 파일명으로 구분합니다. 불필요한 헬퍼와 세분화를 피합니다. 주석에는 필요한 의미와 처리 의도를 남기고 중복 설명이나 문서 참조 지시를 넣지 않습니다.

파일 변경·실행·커밋 전에 구체 범위와 검증 방법을 제시하고 명시적 승인을 받습니다. 방향 합의나 질의응답을 편집 승인으로 간주하지 않습니다. 승인 범위가 실질적으로 확대되면 다시 승인받습니다. 검증 결과는 완료기준과 구분해 작업 결과로 보고합니다.
