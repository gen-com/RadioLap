# 드라이버 라디오 UseCase 계약 초안

[기능 목적](../README.md)을 바탕으로 [Repository](RepositoryContract.md)가 반환한 자료를 정리하고, 라디오 기록 시각에 상황을 연결합니다. 자료 해석과 화면 표시·재생 상태를 맡지 않습니다. 합의한 규칙과 공개 선언을 기록하며 구현·검증 완료를 뜻하지 않습니다.

## 책임과 입출력

DriverRadioUseCase와 구현인 DriverRadioInteractor는 Domain에 둡니다. Interactor는 Repository 계약을 주입받고 네 종류의 독립적인 조회·정리와 이미 받은 자료의 시점 연결을 담당합니다. 별도 RadioContextResolver나 전달만 하는 계층은 추가하지 않습니다.

```swift
protocol DriverRadioUseCase: Sendable {
    func fetchRadioRecords(sessionID: Int, driverNumber: Int) async throws -> [RadioRecord]
    func fetchLaps(sessionID: Int, driverNumber: Int) async throws -> [DriverLap]
    func fetchPositions(sessionID: Int, driverNumber: Int) async throws -> [DriverPosition]
    func fetchStints(sessionID: Int, driverNumber: Int) async throws -> [DriverStint]
    func resolveContext(
        recordedAt: Date,
        laps: [DriverLap]?,
        positions: [DriverPosition]?,
        stints: [DriverStint]?
    ) -> RadioContext
}
```

네 조회 메서드는 해당 Repository 메서드에 세션 ID·드라이버 번호를 전달하고 아래 정리 규칙을 적용합니다. resolveContext는 이미 받은 자료를 이용하는 동기 계산이며 Repository를 호출하지 않습니다. 이 메서드는 오류를 던지지 않고 입력 자료로 결과를 반환하며, 계산 중 취소를 별도로 처리하지 않습니다. 정보 부재·연결 충돌은 결과로 표현합니다. 조회와 정리 전후에 같은 Domain 모델을 사용하고 의미가 같은 후보·최종 모델을 복제하지 않습니다.

화면 진입 입력은 상세에서 받은 Race와 RaceDriver입니다. 화면은 기본 정보를 그대로 보존하며 조회에 race.sessionID와 driver.driverNumber를 사용합니다. Interactor는 이름·시즌·팀을 다시 정규화하거나 조회하지 않으며, RaceDriver.result의 최종 순위를 상황 연결에 사용하지 않습니다.

## 교신 식별자 선언

```swift
struct RadioRecordID: Hashable, Sendable {
    let recordedAt: Date
    let recordingURLString: String
}
```

RadioRecord는 기존 recordedAt·recordingURL을 유지하고 다음 식별자를 계산합니다.

```swift
var id: RadioRecordID {
    RadioRecordID(
        recordedAt: recordedAt,
        recordingURLString: recordingURL.absoluteString
    )
}
```

식별 범위는 한 세션·드라이버의 라디오 화면 안입니다. 선택 상태는 RadioRecordID?로 관리하고 조회 결과에서 해당 교신을 찾습니다. 선택을 위해 레코드 전체를 복제하거나 UUID를 생성하지 않습니다.

## 조회·정리와 반환 보장

### 라디오

- recordedAt과 검증한 recordingURL의 문자열 표현이 모두 같은 레코드는 하나로 합칩니다. 같은 시각이어도 URL이 다르거나 같은 URL이어도 시각이 다르면 별도 교신입니다. 경로·쿼리를 임의 정규화하거나 제거하지 않습니다.
- recordedAt 오름차순, 같은 시각은 위 URL 문자열의 사전순으로 반환합니다. 기기 언어에 따른 비교는 사용하지 않습니다. 동시각의 정렬은 표시를 안정적으로 유지하기 위한 규칙이며 실제 발화 순서를 뜻하지 않습니다.
- 화면 안의 교신 식별은 기록 시각과 위 URL 문자열의 조합입니다. 배열 위치나 새로 생성한 UUID를 사용하지 않습니다. 세션·드라이버는 화면 자체의 식별에 사용하므로 교신마다 반복 저장하지 않습니다.
- 오디오에 미리 접속하거나 파일명을 해석해 실제 발화 시각을 추정하지 않습니다.

### 랩

- 같은 랩 번호의 시작 시각·소요 시간이 모두 같으면 하나로 합칩니다. 사용 값이 다르면 랩 조회 결과 전체를 실패시킵니다.
- 시간 부재를 다른 레코드의 값으로 보충하거나 서로 다른 레코드를 합쳐 완전한 랩을 만들지 않습니다.
- 충돌 검사를 구간 유효성 판단보다 먼저 적용합니다. 구간을 구성할 수 없다는 이유로 충돌하는 레코드를 숨기지 않습니다.

### 순위

- 같은 시각·같은 순위는 하나로 합칩니다. 같은 시각에 서로 다른 순위가 있으면 순위 조회 결과 전체를 실패시킵니다.
- 순위를 재계산하거나 값 사이의 공백을 메우지 않으며, 별도의 최솟값·최댓값 제한을 두지 않습니다.

### 스틴트

- 컴파운드의 앞뒤 공백을 제거하고 공백뿐인 값은 nil로 정리합니다. 알려지지 않은 컴파운드도 보존합니다. 내부 문자열이나 대소문자를 임의 변경하지 않습니다.
- 시작 랩·종료 랩·정리한 컴파운드가 같으면 하나로 합칩니다. 미사용 외부 필드는 중복 비교에 사용하지 않습니다.
- 값의 부재는 보존합니다. 불완전한 스틴트 하나 때문에 다른 정상 스틴트까지 버리지 않습니다.
- 서로 다른 컴파운드의 범위가 겹치면 조회 전체 실패로 바꾸지 않고, 겹치는 랩의 타이어 연결을 불가로 구분합니다.

## 시점 연결

입력은 라디오 기록 절대 시각과 조회·정리에 성공한 랩·순위·스틴트 자료입니다. 같은 세션·드라이버의 자료만 함께 전달하는 책임은 호출자에게 있습니다. 입력 자료만으로 계산하며 현재 시각을 읽거나 외부 자료를 재조회하지 않습니다. 스틴트 재시도 성공 시에도 기존 라디오·랩·순위 자료를 이용해 다시 계산할 수 있어야 합니다.

각 배열의 nil은 아직 사용할 성공 자료가 없다는 뜻이고, 빈 배열은 해당 조회·정리가 성공한 정상 빈 결과입니다. ViewModel이 조회 중·실패·취소의 구분을 유지하며 이를 빈 배열로 바꾸지 않습니다. 랩·순위·스틴트의 반환 배열 순서는 보장하지 않으며 시점 연결 결과는 입력 배열 순서와 무관합니다.

### 연결 결과

```swift
struct RadioContext: Equatable, Sendable {
    let lap: LapContext
    let position: PositionContext
    let tyre: TyreContext
}
```

항목별 결과는 다음 열거형으로 구성합니다. 합의한 선언은 [RadioContext.swift](../Domain/RadioContext.swift)에 작성했으며 DriverRadioInteractor와 함께 컴파일·자동 테스트로 확인했습니다. 범용 상태 타입이나 별도 Resolver를 추가하지 않습니다.

```swift
enum LapContext: Equatable, Sendable {
    case current(number: Int, startsAt: Date, endsAt: Date)
    case lastCompleted(number: Int, endsAt: Date)
    case unavailable
    case conflicting
    case notLoaded
}

enum PositionContext: Equatable, Sendable {
    case recorded(position: Int, recordedAt: Date)
    case unavailable
    case notLoaded
}

enum TyreContext: Equatable, Sendable {
    case current(compound: String)
    case lastCompleted(compound: String)
    case unavailable
    case conflicting
    case incomplete
    case lapUnavailable
    case stintsNotLoaded
}
```

unavailable은 성공 자료로 연결할 정보가 없음을, notLoaded는 사용할 성공 자료가 없음을 뜻합니다. 조회 중·실패·취소는 ViewModel이 구분합니다. 타이어의 랩 번호·근거 시각은 같은 RadioContext.lap을 사용합니다.

| 결과 타입 | 경우 | 함께 보존할 값 |
| --- | --- | --- |
| LapContext | 현재 랩 연결 | 랩 번호·시작·종료 절대 시각 |
| LapContext | 마지막 완료 랩 | 랩 번호·종료 절대 시각 |
| LapContext | 정보 없음 / 충돌 / 자료 미준비 | — |
| PositionContext | 순위 연결 | 순위·기록 절대 시각 |
| PositionContext | 정보 없음 / 자료 미준비 | — |
| TyreContext | 현재 랩의 타이어 / 마지막 완료 랩의 타이어 | 컴파운드 |
| TyreContext | 정보 없음 / 충돌 / 불완전 자료 | — |
| TyreContext | 랩 연결 불가 / 스틴트 자료 미준비 | — |

타이어의 랩 번호·근거 시각은 같은 RadioContext.lap을 사용하며 중복 저장하지 않습니다. 순위는 랩과 독립적으로 연결합니다. 조회 실패·취소·로딩과 표시 문구는 결과 타입에 넣지 않고 ViewModel이 가진 조회 상태와 함께 표시합니다. 경과 시간은 라디오 기록 시각과 보존한 근거 시각으로 계산할 수 있습니다.

### 랩 구간

- 시작 시각과 소요 시간이 모두 있고 소요 시간이 양수인 랩에서 종료 시각을 시작 시각 + 소요 시간으로 계산합니다.
- 시작 이상·종료 미만 구간에 라디오 기록 시각이 포함되는 랩을 연결합니다.
- 시간이 없거나 소요 시간이 0 이하이거나 숫자 연산으로 종료 시각을 표현할 수 없으면 해당 랩의 구간을 구성하지 않으며 마지막 완료 랩 계산에도 사용하지 않습니다. 다른 정상 랩은 유지합니다.
- 다음 랩 시작 시각으로 끝을 보충하거나, 구간의 공백·겹침을 임의 보정하지 않습니다. 두 랩 이상에 포함되면 현재 랩 연결 충돌로 구분하며 마지막 완료 랩으로 대체하지 않습니다.
- 연결 가능한 구간이 없어도 라디오 기록을 제외하지 않습니다. 근사 시작 시각과 라디오 기록 시각으로 연결한 결과이지 실제 발화 순간의 확정된 랩이 아닙니다.

### 마지막 확인 랩

- 라디오 기록 시각을 포함하는 랩 구간이 없을 때, 해당 시각과 같거나 그보다 앞서 종료된 랩 중 가장 최근 랩을 마지막 확인 정보로 제공합니다.
- 종료 시각과 라디오 시각이 같으면 현재 랩에서는 제외하지만 마지막 완료 랩 후보에는 포함합니다. 그 시각에 시작하는 랩이 있으면 현재 랩 연결 규칙을 먼저 적용합니다.
- 가장 최근 종료 시각이 같은 여러 랩이 있으면 임의로 하나를 고르지 않고 마지막 확인 랩을 결정할 수 없는 충돌로 구분합니다.
- 랩 종료 시각과 라디오 기록 시각의 차이를 계산할 수 있게 근거 시각을 보존합니다. 경과 시간의 표시 형식은 View가 정합니다.
- 이전 랩만 확인된다는 이유로 레이스가 종료됐다고 단정하지 않습니다. 마지막 확인 정보는 해당 시각에 연결된 정보와 구분합니다.

### 순위

- 라디오 기록 시각과 같거나 그보다 앞선 기록 중 가장 최근 순위를 연결합니다. 이후 기록을 거꾸로 적용하지 않습니다.
- 해당 기록의 시각을 함께 보존합니다. 근거 없이 몇 초 이상이면 무효로 처리하는 제한은 두지 않습니다.
- 이전 기록이 없으면 연결할 순위 정보가 없습니다. 랩·타이어 연결 여부와 독립적으로 계산하며 상세의 최종 순위로 대체하지 않습니다.

### 타이어

- 연결된 랩 번호가 스틴트의 시작 랩 이상·종료 랩 이하이면 해당 컴파운드를 연결합니다.
- 시작·종료 랩 또는 컴파운드가 없으면 그 레코드로 타이어를 확정하지 않습니다. 종료 랩이 시작 랩보다 작아도 연결에 사용하지 않으며 값을 뒤집어 보정하지 않습니다.
- 범위가 확인되는 스틴트에서 컴파운드만 없고 정상 스틴트와 겹치면, 해당 랩의 타이어는 연결 불가입니다. 확인 가능한 불확실성을 무시하고 정상 값만 선택하지 않습니다.
- 범위 자체를 확인할 수 없는 레코드나 역전 범위의 영향 구간을 추정하지 않습니다. 다른 정상 범위의 정보는 유지합니다.
- 서로 다른 컴파운드가 겹치는 랩은 임의로 하나를 고르지 않습니다. 해당하는 스틴트가 없는 경우와 충돌로 결정할 수 없는 경우를 구분합니다.
- 서로 다른 스틴트 범위가 겹치더라도 해당 랩에 적용되는 컴파운드가 모두 같고 부재 정보가 없다면 그 타이어를 제공합니다.
- 마지막 완료 랩에 연결되는 타이어를 제공할 때는 랩과 함께 마지막 확인 정보로 구분합니다. 이를 라디오 시각의 확정된 타이어로 표시하지 않습니다.
- 타이어 연결에는 랩이 필요합니다. 스틴트 조회가 성공했어도 랩 조회가 실패했다면 타이어 정보 부재로 처리하지 않으며, 그 의존 관계를 Presentation에서 구분할 수 있어야 합니다.

복합 사유가 있으면 아래 순서로 처음 해당하는 결과를 반환합니다. 이는 결과를 결정하는 우선순위이며 내부 함수 호출 순서를 강제하지 않습니다.

| 순서 | 조건 | TyreContext 결과 |
| --- | --- | --- |
| 1 | 현재 랩 또는 마지막 완료 랩을 결정할 수 없음 | 랩 연결 불가 |
| 2 | 랩은 결정됐지만 스틴트 성공 자료가 없음 | 스틴트 자료 미준비 |
| 3 | 해당 랩에 서로 다른 컴파운드가 존재 | 충돌 |
| 4 | 해당 랩을 포함하는 유효 범위에 컴파운드 부재가 존재 | 불완전 자료 |
| 5 | 적용 가능한 스틴트가 없음 | 정보 없음 |
| 6 | 적용되는 컴파운드가 모두 같음 | 현재 또는 마지막 확인 타이어 |

랩과 스틴트가 모두 미준비이면 랩 연결 불가를 반환합니다. 컴파운드 충돌과 부재가 함께 있으면 충돌을 우선합니다. 반환 결과가 하나여도 ViewModel은 개별 조회 상태를 유지하여 다른 실패·미준비 사실을 잃지 않습니다.

## 실패·취소와 화면 책임의 경계

Repository 실패를 숨기거나 빈 성공으로 바꾸지 않습니다. 같은 랩 번호의 충돌은 랩 조회·정리 실패, 같은 시각의 순위 충돌은 순위 조회·정리 실패입니다. 다른 자료의 성공 결과는 유지합니다. 스틴트 겹침과 구간을 구성할 수 없는 값은 위 연결 규칙을 적용하며 전체 실패 정책과 구분합니다.

네 조회·정리 메서드는 조회 전, Repository 반환 후와 자체 정리 결과 반환 전에 호출 취소를 확인하고 Repository에도 취소를 전달합니다. 동기 상황 연결인 resolveContext에는 이 취소 처리를 적용하지 않습니다. 관찰한 취소는 CancellationError로 전달합니다. 일반 오류 전달 직전에 호출 취소가 관찰되면 CancellationError를 전달하고, 이미 반환한 결과는 뒤늦은 취소로 바꾸지 않습니다. 한 조회의 실패 때문에 다른 종류의 조회를 취소하지 않습니다.

ViewModel은 자료별 조회 상태, 실패한 조회만 재시도, 취소와 늦은 결과 차단을 담당합니다. 화면 표시 문구·날짜 형식·선택·이동과 플레이어의 재생 상태를 Domain 결과에 넣지 않습니다. 오디오 접속·재생 실패는 자료 정리나 시점 연결 실패와 별개입니다.

## 검증 경계와 후속 작업

UseCase 검증은 Repository 대역이 제공한 Domain 자료로 중복·충돌·시간순 정렬과 조회별 실패·취소를 확인합니다. 시점 연결은 같은 입력 자료에 대한 랩·순위·타이어와 마지막 확인 정보, 연결 불가의 의미를 검증합니다. JSON 형식과 실제 오디오 재생은 이 검증의 대상이 아닙니다. Repository 대역으로 Domain 자료를 공급하는 조회·정리와 시점 연결 테스트가 통과했습니다. [완료기준](CompletionCriteria.md)의 실제 화면·재생 연동 검증은 이 결과와 구분합니다.

메서드와 결과의 의미는 위 합의를 따릅니다. 결과 열거형과 교신 식별자의 선언은 위에 반영했습니다. 화면의 context(for:)는 현재 자료로 오류를 던지지 않는 resolveContext를 호출합니다. 조회·정리의 취소와 동기 상황 연결을 구분하며, 완료기준에서 계약 기반 테스트를 도출하고 구현으로 이어갑니다.
