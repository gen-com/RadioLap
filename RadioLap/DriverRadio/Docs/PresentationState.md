# 드라이버 라디오 화면 상태와 동작 초안

[기능 목적](../README.md), [UseCase 계약](UseCaseContract.md)과 [재생 계약](PlaybackContract.md)을 바탕으로 화면의 책임과 동작을 정의합니다. 합의한 동작을 기록한 문서이며 구현·검증 완료를 뜻하지 않습니다.

## 책임과 입력

상세에서 선택한 Race와 RaceDriver를 입력으로 받습니다. 화면 수명 동안 기본 정보를 보존하고 조회에는 race.sessionID와 driver.driverNumber를 사용합니다. 이름·순위로 식별하지 않으며 기본 정보를 다시 조회하거나 별도 진입 모델로 복제하지 않습니다.

| 담당 | 책임 |
| --- | --- |
| ViewModel | 자료별 조회 상태와 요청 유효성, 선택한 교신, 상황 연결 결과, 선택·접기에 따른 재생 제어 |
| 재생 담당 객체 | 오디오 준비·재생·일시정지, 진행 위치와 중단 이벤트 처리 |
| View | 상태 배치·시각 표현·이벤트 전달, 상세 복귀와 스크롤 위치 관리 |
| Component | UseCase와 재생 담당 객체의 조립·제공. 화면·재생 상태는 직접 소유하지 않음 |

교신 선택은 재생 중지와 상황 표시가 함께 바뀌는 동작이므로 ViewModel에서 관리합니다. 화면 이동용 선택과 구분합니다. ViewModel은 UseCase에 상황 연결을 요청하며 중복 정리·시점 연결 규칙이나 외부 응답 해석을 반복하지 않습니다. 하위 View에는 필요한 데이터와 이벤트를 전달합니다.

## 공개 상태·동작과 객체 수명

View가 사용하는 공개 계약과 ViewModel 구현을 분리합니다. 공개 상태는 기본 정보, 자료별 조회 상태, 선택한 교신, 상황 연결 결과, 재생 상태로 구분합니다. 재생 상태의 원본은 재생 담당 객체가 관리하고 ViewModel은 화면에 필요한 상태로 전달하며 별도의 재생 상태를 독립적으로 변경하지 않습니다.

다음 공개 선언은 [Presentation/ViewModel](../Presentation/ViewModel/)에 둡니다.

```swift
enum RadioLoadState<Value: Equatable & Sendable>: Equatable, Sendable {
    case idle
    case loading
    case loaded(Value)
    case failed
    case cancelled
}

enum RadioDataKind: Sendable {
    case radio
    case laps
    case positions
    case stints
}

@MainActor
protocol DriverRadioPresentation: AnyObject, Observable {
    var race: Race { get }
    var driver: RaceDriver { get }
    var radioState: RadioLoadState<[RadioRecord]> { get }
    var lapsState: RadioLoadState<[DriverLap]> { get }
    var positionsState: RadioLoadState<[DriverPosition]> { get }
    var stintsState: RadioLoadState<[DriverStint]> { get }
    var selectedRadioID: RadioRecordID? { get }
    var playbackState: RadioPlaybackState { get }
    var playbackPosition: TimeInterval? { get }
    var playbackDuration: TimeInterval? { get }

    func load()
    func retry(_ data: RadioDataKind)
    func selectRadio(_ id: RadioRecordID)
    func play()
    func pause()
    func deactivate()
    func leave()
    func context(for id: RadioRecordID) -> RadioContext?
}
```

RadioLoadState는 라디오 Presentation 안에서만 사용하며 앱 전체 공통 계층으로 올리지 않습니다. loaded([])는 정상 빈 결과입니다. 실패의 내부 오류를 그대로 노출하지 않고 자료 종류에 맞는 안내를 표시합니다. 공개 상태는 외부에서 읽기만 가능하며 변경을 관찰할 수 있습니다. 재생 관련 값은 주입받은 RadioPlayback의 현재 상태를 전달합니다.

| 공개 동작 | 보장 조건 |
| --- | --- |
| load() | 최초 네 자료 조회를 시작. 같은 화면에서 반복 호출되어도 진행 중이거나 완료된 조회를 다시 시작하지 않음 |
| retry(_:) | 지정한 자료가 실패·취소 상태일 때만 다시 요청 |
| selectRadio(_:) | 같은 교신은 접고 다른 교신은 선택. 목록에 없는 식별자는 무시 |
| play() | 선택한 교신 재생. 일시정지는 이어 듣고 실패·종료는 처음부터 시작. 선택 없음·준비 중·재생 중에는 중복 요청하지 않음 |
| pause() | 위치를 보존하며 일시정지 |
| deactivate() | 앱 비활성화를 전달해 준비 중 자동 재생도 차단 |
| leave() | 조회 취소·무효화와 재생 중지·초기화 |

이 동작들은 응답을 기다리지 않고 반환하며 결과를 공개 상태로 제공합니다.

구체 ViewModel은 다음 입력으로 생성합니다. 프로토콜의 초기화 요구사항은 아닙니다.

```swift
init(
    race: Race,
    driver: RaceDriver,
    useCase: any DriverRadioUseCase,
    playback: any RadioPlayback
)
```

초기화만으로 조회·재생하지 않습니다. 조회 상태는 idle, 선택은 없음으로 시작하고 화면 진입 시 load()를 호출합니다.

### 상황 연결 결과 읽기

context(for:)는 현재 목록의 교신이면 UseCase를 통해 계산한 RadioContext를 제공합니다. 상황 자료가 없으면 notLoaded 등 자료 미준비를 포함한 결과를 제공하며, 목록에 없는 식별자에만 nil을 반환합니다. 조회·선택·재생 상태를 바꾸지 않습니다. 접힌 교신의 랩도 이 결과로 표시하며 View가 원본 자료에서 상황을 계산하지 않습니다.

context(for:)를 읽을 때 현재 목록에서 교신을 찾아 그 기록 시각과 현재 성공 자료로 UseCase의 resolveContext를 동기 호출합니다. 계산은 오류를 던지지 않으며 별도 결과 캐시나 계산 요청 상태를 두지 않습니다. 조회·정리 작업의 취소와 늦은 응답 차단은 기존 요청 계약대로 유지합니다.

라디오 화면에 진입할 때마다 새 ViewModel과 전용 재생 객체로 시작합니다. Component가 UseCase와 재생 객체의 의존성을 조립하며 여러 라디오 화면이 재생 객체를 공유하지 않습니다. 진입 View는 화면 수명 동안 ViewModel을 유지하고 다시 그려질 때마다 재생 객체를 생성하지 않습니다. ViewModel은 UseCase와 재생 계약을 주입받으며 Component 전체나 구체 오디오 구현에 의존하지 않습니다.

상세 복귀 시 객체 해제를 기다리지 않고 조회 취소와 재생 중지를 수행합니다. 재진입에는 이전 선택·위치·이벤트가 이어지지 않습니다. 앱 전환 후에도 같은 화면이 유지되면 같은 객체와 위치를 보존합니다. 공개 상태·동작과 상황 계산은 위 계약을 따릅니다.

## 진입과 기본 정보

- 진입 즉시 레이스 이름·시즌과 드라이버 이름·팀을 표시합니다. 조회 중·빈 결과·실패·취소 상태에서도 유지하며 최종 순위는 기본 정보에 포함하지 않습니다.
- 팀 정보가 없으면 상세와 동일하게 “팀 정보 없음”을 표시합니다.
- 진입 시 라디오·랩·순위·스틴트를 독립적으로 조회합니다. 모든 자료의 성공을 기다리는 단일 화면 로딩 상태로 묶지 않습니다.
- 라디오가 준비되면 상황 자료를 기다리지 않고 목록을 표시합니다. UseCase의 반환 순서를 유지하며 기록 시각과 연결 가능한 랩을 교신 선택의 단서로 표시합니다. 랩 정보가 없어도 선택할 수 있습니다.
- 최초에는 모든 교신을 접어두고 자동 선택·재생하지 않습니다.

## 자료별 조회 상태와 재시도

각 자료는 조회 전·조회 중·성공·실패·취소를 구분합니다. 성공한 빈 배열과 아직 성공 자료가 없는 상태를 혼동하지 않습니다. 네 자료는 위 RadioLoadState로 같은 상태 의미를 공유하되 각각 독립적으로 관리합니다.

| 대상과 결과 | 표시와 동작 |
| --- | --- |
| 라디오 조회 중 | 목록 영역에서 진행 중임을 표시 |
| 라디오 성공, 기록 있음 | 시간순 교신 목록 표시 |
| 라디오 성공, 빈 결과 | “공개된 라디오 기록이 없습니다” 표시. 실제 교신이 없었다고 단정하지 않음 |
| 라디오 실패 | 목록 영역에서 실패 안내와 라디오 재시도 제공 |
| 상황 자료 조회 중 | 해당 항목이 준비 중임을 표시. 라디오 목록과 재생은 유지 |
| 상황 자료 실패 | 해당 자료의 실패와 재시도 제공. 다른 성공 자료는 유지 |
| 화면에 머무는 동안 유효 요청 취소 | 실패와 구분하고 해당 자료를 다시 불러올 수 있게 함. 자동 재시도하지 않음 |

재시도는 실패하거나 취소된 자료만 다시 요청합니다. 다른 성공 자료와 선택한 교신·재생을 유지하며, 상황 자료가 준비되면 기존 성공 자료와 함께 상황 연결 결과만 갱신합니다. UseCase에는 사용할 성공 자료가 없으면 nil, 정상 빈 결과이면 빈 배열을 전달합니다.

요청 유효성은 자료 종류마다 독립적으로 관리합니다. 같은 종류의 요청이 교체되거나 취소되면 이전 요청을 무효화하며, 늦은 성공·실패·취소는 현재 상태를 바꾸지 않습니다. 이전 요청의 종료로 현재 요청의 진행 표시를 끝내지 않습니다. 한 종류의 실패가 다른 종류의 요청을 취소하지 않습니다.

## 교신 선택과 접기

교신 식별은 UseCase 계약의 기록 시각과 URL 문자열 조합을 사용합니다. 배열 위치나 새 UUID로 식별하지 않습니다.

| 사용자 동작 | 선택·표시·재생 처리 |
| --- | --- |
| 접힌 교신 선택 | 해당 교신 하나만 펼쳐 재생 영역과 상황 정보를 표시. 자동 재생하지 않음 |
| 펼친 교신 다시 선택 | 접고 선택을 해제. 재생을 중지하고 위치를 초기화 |
| 다른 교신 선택 | 기존 교신을 접고 재생을 중지·초기화. 새 교신을 펼쳐 재생 대기 |

재생 중지에는 준비 중인 오디오가 나중에 재생되지 않게 하는 처리도 포함합니다. 오디오 실패로 교신을 접거나 상황 정보를 지우지 않습니다. 재생·일시정지·종료와 재시도는 [재생 계약](PlaybackContract.md)을 따릅니다.

## 상황 정보와 연결 근거

영역 제목은 “기록 시각 주변의 상황”으로 표시하고, 라디오 기록 시각이 실제 발화 시각과 다를 수 있음을 안내합니다. 확인할 수 있는 랩·순위·타이어는 독립적으로 표시하며 드라이버의 의도나 교신 원인을 단정하지 않습니다.

| 연결 결과 | 표시 방향 |
| --- | --- |
| 현재 랩 연결 | 연결된 랩 번호 |
| 마지막 완료 랩 | “마지막 확인” 구분과 랩 번호, 종료 시각부터 라디오 기록 시각까지의 경과 시간 |
| 순위 연결 | 순위와 해당 순위의 기록 시각 |
| 타이어 연결 | 컴파운드. 마지막 완료 랩 기준이면 마지막 확인 정보임을 함께 표시 |
| 성공 자료로 연결할 정보가 없음 | “연결할 정보 없음” |
| 충돌·불완전 자료로 결정할 수 없음 | “정보를 확정할 수 없음”과 확인된 사유 |

조회 중·실패·취소는 위 연결 결과와 구분합니다. 랩 조회 실패로 타이어를 연결할 수 없으면 “타이어를 연결하려면 랩 정보가 필요합니다”라고 안내하고 랩 재시도를 제공합니다. 재시도 성공만으로 타이어 연결이 반드시 가능해진다고 보장하지 않습니다. 랩과 스틴트가 함께 실패한 경우에도 개별 조회 상태를 유지하며 한쪽 실패를 숨기지 않습니다. 연결 불가 사유의 우선순위는 UseCase 계약을 따릅니다.

핵심 정보는 바로 보여주고 “상황을 연결한 기준”을 펼치면 다음 근거를 확인할 수 있게 합니다.

- 랩: 연결에 사용한 시작·종료 시각 또는 마지막 완료 랩의 종료 시각
- 순위: 적용한 순위 기록 시각
- 타이어: 기준 랩과 그 랩을 포함하는 스틴트 자료로 연결했다는 규칙
- 연결 불가: 자료 부재·충돌·불완전 등 반환 결과로 확인할 수 있는 사유

개별 스틴트의 시작·종료 랩을 나열하지 않으며 표시를 위해 RadioContext를 확장하지 않습니다. 충돌한 원본 레코드를 추정하거나 Domain에서 제공하지 않은 세부 근거를 만들어내지 않습니다.

## 오디오 정보 표시

- 준비 중에는 “오디오를 준비하는 중입니다”와 진행 표시를 제공합니다.
- 전체 길이를 모르면 확인 가능한 재생 경과 시간만 표시하고 전체 길이나 진행률을 0으로 추정하지 않습니다.
- 재생 위치도 모르면 시간 표시를 생략하고 현재 재생 상태를 보여줍니다.
- 실패 시 “오디오를 재생하지 못했습니다”와 ‘다시 시도’를 표시하며 선택한 교신과 상황 정보는 유지합니다.
- 정보가 준비되면 표시만 갱신하고 재생을 다시 시작하지 않습니다.

## 기록 시각 표시

- 교신 기록 시각은 기기 시간대를 적용해 초 단위까지 표시합니다. 목록 상단에 적용한 시간대를 표시합니다.
- 교신 기록의 날짜가 달라지면 날짜도 구분해 표시합니다. 연결 근거의 시각에도 같은 시간대를 적용합니다.
- 시간대가 바뀌면 다시 표시할 때 현재 시간대를 적용합니다. 교신 순서·선택·재생·상황 연결 결과는 유지하고 재조회하지 않습니다.
- 원본 절대 시각과 기록 시각 기준의 연결은 바꾸지 않습니다. 와이어프레임의 싱가포르 현지 시각은 표시 정책을 고정하는 요구사항이 아닙니다.

## 화면 이탈과 복귀

상세로 돌아가면 재생을 중지하고 위치를 초기화하며, 진행 중인 조회를 취소·무효화합니다. 실제 작업 종료를 기다리지 않고 복귀하며 이후 응답은 반영하지 않습니다. 상세의 기존 결과와 보던 스크롤 위치를 유지하고 재조회하지 않는 기존 계약을 보존합니다.

같은 드라이버를 다시 선택해 진입하면 새로 조회하며 이전 교신 선택·재생 위치를 복원하지 않습니다. 앱 전환·잠금·전화 등으로 라디오 화면이 유지된 채 재생이 중단되는 경우는 상세 복귀와 구분하고 [재생 계약](PlaybackContract.md#비활성화와-외부-중단)을 따릅니다.

## 검증 경계와 후속 작업

ViewModel의 자료별 상태·요청 유효성·선택·재생 제어는 UseCase와 재생 대역으로 검증합니다. 배치·시각 표현·근거 펼치기·복귀와 스크롤은 직접 화면 검증과 구분합니다.

공개 상태·동작의 의미와 객체 수명은 위 기준을 따릅니다. context(for:)는 캐시 없는 동기 계산으로 사용하고 재생 상태·위치·길이는 재생 계약의 관찰 상태를 전달합니다. 외부 개입의 검증 범위는 재생 계약을 따릅니다.
