# 드라이버 라디오 재생 계약 초안

[기능 목적](../README.md)과 [화면 계약](PresentationState.md)을 바탕으로 오디오 재생의 책임과 보장 동작을 정의합니다. AVPlayer 연동을 구현하고 컴파일과 이벤트 연결 코드를 확인했습니다. 공개 선언은 아래 합의를 따릅니다. 실제 오디오는 AVPlayer로 연동하고 앱의 재생 정책은 RadioPlayback 구현이 담당합니다.

## 책임과 입출력

재생 담당 객체는 선택한 교신의 오디오 URL과 재생·일시정지·중지 요청을 받아 오디오를 준비하고 재생합니다. 준비·재생·일시정지·종료·실패 상태와 진행 위치, 외부 중단을 화면에서 구분할 수 있게 제공합니다. 공개 상태는 관찰 가능하고 외부에서는 읽기만 합니다. 구체 선언은 아래를 따릅니다.

조회·상황 연결·교신 선택은 맡지 않습니다. ViewModel은 선택한 교신에 대한 제어 요청을 전달하고 재생 상태를 화면 상태에 연결합니다. Component는 필요한 의존성을 조립해 제공하며 재생 상태를 직접 소유하지 않습니다.

오디오 URL의 형식 검증은 Repository 책임입니다. 접속·오디오 준비·재생 실패는 재생 책임에서 처리하고 라디오 조회 실패나 상황 연결 실패로 바꾸지 않습니다. 교신 선택만으로 접속·자동 재생하지 않으며 사용자가 재생을 요청할 때 준비합니다.

## 공개 상태와 동작

```swift
@MainActor
protocol RadioPlayback: AnyObject, Observable {
    var state: RadioPlaybackState { get }
    var position: TimeInterval? { get }
    var duration: TimeInterval? { get }

    func play(url: URL)
    func resume()
    func pause()
    func stop()
    func deactivate()
}

enum RadioPlaybackState: Equatable, Sendable {
    case idle
    case preparing
    case playing
    case paused
    case ended
    case failed
}
```

위 공개 선언은 [RadioPlayback.swift](../Playback/RadioPlayback.swift)에 작성했습니다. RadioPlayer의 정책 구현을 컴파일하고 연동 대역 테스트를 통과했습니다. AVPlayer 연동과 화면 연결을 구현했습니다. 위치·전체 길이는 초 단위이며 모르면 각각 nil입니다.

- play(url:)은 기존 재생을 교체하고 처음부터 시작합니다.
- resume()은 일시정지 위치에서 이어 듣습니다.
- pause()와 deactivate()는 위치를 보존하며 준비 중 자동 재생도 막습니다.
- stop()은 기존 작업을 무효화하고 대기 상태로 초기화합니다.

ViewModel에는 이 계약만 주입하고 구체 오디오 구현은 Component에서 조립합니다.

| 상태 | 의미 |
| --- | --- |
| 대기 | 아직 재생을 요청하지 않았거나 중지·초기화됨 |
| 준비 중 | 최초 오디오 준비 또는 재생 중 데이터 대기 |
| 재생 중 | 오디오 재생 중 |
| 일시정지 | 위치를 유지한 채 멈춤 |
| 종료 | 끝까지 재생함 |
| 실패 | 준비·재생에 실패하여 재시도 가능 |

현재 위치와 전체 길이는 각각 확인된 값만 제공하고 모르면 정보 부재로 표현합니다. 재생 상태의 원본은 이 객체가 관리하며 ViewModel은 이를 화면에 전달합니다.

공개 동작은 URL을 받아 처음부터 재생, 일시정지 후 이어 재생, 일시정지, 중지·초기화로 나눕니다. 실패 후 재시도와 종료 후 다시 듣기는 같은 URL을 처음부터 재생하는 동작을 사용합니다. 앱 비활성화는 화면에서 ViewModel을 통해 전달받고, 전화·이어폰 연결 해제 같은 오디오 중단은 재생 담당 객체가 처리합니다.

재생 객체는 라디오 화면마다 전용으로 조립하며 해당 화면의 ViewModel이 사용합니다. 화면이 다시 그려질 때마다 새로 만들거나 여러 화면이 공유하지 않습니다. 상세 복귀 시 명시적으로 중지하고 새 진입에서는 새 객체를 사용합니다. 같은 화면이 유지되는 앱 전환에서는 객체와 위치를 보존합니다.

## AVPlayer 연동과 테스트 경계

앱의 재생 정책을 가진 RadioPlayback 구현 객체 하나와 AVPlayer를 연결하는 작은 경계 하나로 구성합니다. 이벤트별 관리자나 별도 상태 처리 계층은 만들지 않습니다. AVPlayer의 모든 기능을 감싸는 범용 계층도 두지 않습니다.

| 경계를 통과하는 정보 | 범위 |
| --- | --- |
| 명령 | URL 준비, 재생, 일시정지, 중지 |
| 이벤트 | 준비·대기, 실제 재생, 위치·길이, 종료, 실패, 외부 중단 |

실제 연동은 AVPlayer에 명령을 전달하고 상태·진행 이벤트를 전달합니다. 오디오 중단·출력 경로 변경은 AVAudioSession 알림에 연결합니다. 앱 비활성화는 기존 화면 계약대로 ViewModel을 통해 전달합니다. 자동 재개 여부와 늦은 이벤트 반영 여부는 RadioPlayback 구현이 재생 의도와 현재 작업을 기준으로 결정합니다. 연동 경계에 이 정책을 중복 구현하지 않습니다.

테스트에서는 이 경계를 대역으로 바꿔 이벤트 발생 순서를 제어하고 재생·일시정지·중지 명령을 기록합니다. 테스트 대상은 실제 RadioPlayback 구현이며, RadioPlayback 대역 자체의 동작을 테스트하지 않습니다.

공식 연동 근거는 [AVPlayer 재생 상태](https://developer.apple.com/documentation/avfoundation/avplayer/timecontrolstatus-swift.property), [오디오 중단](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions), [출력 경로 변경](https://developer.apple.com/documentation/avfaudio/responding-to-audio-route-changes)을 참고합니다. 문서 확인은 앱 연동 검증을 뜻하지 않습니다.

### 최소 명령·이벤트 선언

연동 경계는 RadioAudioTransport로 이름 짓고 기능의 Playback 영역에 둡니다. 다음 선언은 [RadioAudioTransport.swift](../Playback/RadioAudioTransport.swift)에 작성했습니다. 컴파일과 연동 대역 테스트를 확인했으며 실제 연동 구현은 [AVPlayerRadioAudioTransport.swift](../Playback/AVPlayerRadioAudioTransport.swift)에 있습니다. 프로토콜과 이벤트는 하나의 파일에 함께 두고 별도 이벤트 관리자나 작업 식별자 타입은 추가하지 않습니다.

```swift
@MainActor
protocol RadioAudioTransport: AnyObject {
    func prepare(
        url: URL,
        onEvent: @escaping @MainActor @Sendable (RadioAudioEvent) -> Void
    )
    func play()
    func pause()
    func stop()
}

enum RadioAudioEvent: Sendable {
    case ready
    case waiting
    case playing
    case progress(position: TimeInterval?, duration: TimeInterval?)
    case ended
    case failed
    case interrupted
}
```

| 명령 | 연동 경계의 책임 |
| --- | --- |
| prepare(url:onEvent:) | 이전 오디오를 정리하고 새 URL을 처음부터 준비한다. 준비만으로 재생하지 않으며 해당 준비 요청의 이벤트를 콜백에 전달한다. |
| play() | 현재 준비한 오디오에 재생 명령을 전달한다. 일시정지 후에는 위치를 초기화하지 않는다. |
| pause() | 현재 오디오를 일시정지하며 위치를 보존한다. 이미 전달한 재생 명령이 대기 해소 후 계속 실행되지 않도록 실제 플레이어에도 반영한다. |
| stop() | 현재 오디오를 중지·해제한다. 이후 재생은 새 준비 요청으로 시작한다. |

이벤트는 준비 완료 또는 대기 해소(ready), 데이터 대기(waiting), 실제 재생 시작(playing)을 구분합니다. ready 자체는 재생 명령이 아닙니다. RadioPlayback 구현이 현재 작업과 재생 의도를 확인해 필요할 때만 play()를 요청하며, 상태를 playing으로 확정하는 근거는 playing 이벤트입니다. waiting은 위치를 지우지 않으며 기존 계약의 preparing으로 표현합니다.

progress의 두 값은 해당 이벤트 시점에 확인된 초 단위 위치·길이입니다. 각각 nil이면 그 정보를 알 수 없다는 뜻이며, 변경되지 않은 필드를 생략하는 부분 갱신 표시가 아닙니다. ended와 failed는 현재 작업의 종료·실패를 알립니다. interrupted는 일시정지가 필요한 외부 중단을 알리며, 원인별 별도 재생 정책은 추가하지 않습니다. 앱 비활성화는 기존대로 RadioPlayback.deactivate()에 전달합니다.

### 작업 구분과 중단 책임

- prepare마다 전달한 콜백은 해당 준비 작업에 속합니다. 같은 URL을 다시 준비해도 다른 작업이며 URL로 최신 여부를 판단하지 않습니다.
- RadioPlayback 구현이 준비 요청의 콜백에 내부 작업 표식을 연결하고 교체·중지 시 무효화합니다. 연동 경계는 이전 작업에서 발생한 이벤트를 새 콜백의 이벤트로 바꿔 전달하지 않습니다.
- 일시정지·외부 중단은 같은 작업의 위치를 보존하면서 재생 의도를 해제합니다. 같은 작업의 늦은 ready·waiting·playing도 그 의도를 되살리지 않습니다. 이전 작업의 콜백을 무시하는 것과 현재 오디오에 pause·stop 명령을 전달하는 것은 별개이며 둘 다 필요한 책임입니다.
- 명령과 콜백은 MainActor에서 처리합니다. 명령의 실패는 failed 이벤트로 전달하며 이벤트가 반드시 다음 비동기 작업에서 도착한다고 가정하지 않습니다. 준비 작업은 prepare 호출 전에 구분할 수 있어야 합니다.
- 실제 연동은 교체·중지 시 기존 오디오와 관찰을 정리합니다. 정책 객체는 이미 전달 중인 이벤트가 늦게 도착할 수 있음을 전제로 처리합니다. 테스트 대역도 이전 콜백을 보관해 이러한 이벤트를 전달할 수 있게 하며 최신 작업 판정을 대신하지 않습니다.

테스트는 준비 요청별 URL·콜백과 play·pause·stop 명령을 기록하는 대역을 사용합니다. 동일 URL 재시작, 준비·대기 중 중단, 교체·중지 후 이전 콜백의 이벤트를 실제 RadioPlayback 구현에 전달해 공개 상태와 후속 명령을 확인합니다. AVPlayer·AVAudioSession의 구체 알림을 위 이벤트로 변환하는 코드는 검토했습니다.

## 재생과 위치

| 요청 또는 사건 | 보장 동작 |
| --- | --- |
| 선택한 교신 재생 요청 | 오디오를 준비한 뒤 재생. 준비 중임을 알리고 중복 요청을 막음 |
| 재생 중 일시정지 | 재생 위치를 유지하며 멈춤 |
| 일시정지 후 재생 요청 | 멈춘 위치에서 이어 재생 |
| 끝까지 재생 | 종료를 알림. 선택·상황 정보는 유지하며 다음 교신을 자동 재생하지 않음 |
| 종료 후 재생 요청 | 같은 교신을 처음부터 재생 |
| 교신 접기·다른 교신 선택·상세 복귀 | 기존 오디오를 중지하고 재생 위치를 초기화 |
| 오디오 실패 후 사용자 재시도 | 같은 오디오를 다시 준비해 처음부터 재생 |

한 번에 선택한 교신 하나만 재생합니다. 중지되거나 교체된 오디오의 늦은 준비 완료·진행·종료·실패가 현재 재생 상태를 변경하거나 소리를 내지 않게 합니다. 이는 특정 취소 API의 즉시 종료에 의존하지 않는 보장입니다.

재생 실패가 발생해도 선택한 교신과 상황 정보는 유지하고 재시도를 제공합니다. 재생 재시도로 라디오·랩·순위·스틴트를 다시 조회하지 않습니다. 상황 자료의 도착이나 재시도 성공도 오디오를 다시 시작하거나 위치를 초기화하지 않습니다.

### 재생 중 데이터 대기

재생 도중 데이터를 기다릴 때는 별도 버퍼링 상태를 추가하지 않고 preparing으로 “오디오를 준비하는 중입니다”를 표시합니다. 확인된 현재 위치를 유지하고, 사용자의 재생 의도가 유지되면 데이터가 준비된 뒤 이어 재생합니다.

데이터 대기는 이미 완료한 최초 준비를 무효화하지 않습니다. 준비된 오디오를 대기 중 일시정지한 뒤 사용자가 이어 듣기를 요청하면 추가 ready 알림을 기다리지 않고 play()를 전달합니다. 이후 필요한 버퍼 대기는 실제 플레이어가 처리하며 playing 이벤트 전까지 준비 중으로 표시합니다. 최초 준비가 아직 완료되지 않았다면 기존대로 준비 완료를 기다립니다.

대기 중 일시정지·앱 비활성화·오디오 중단·이어폰 연결 해제·교신 변경·중지가 발생하면 이전 요청으로 자동 재생하지 않습니다. 데이터 준비 완료만으로 중단 상태를 덮어쓰지 않으며, 외부 중단 후 다시 활성화되는 것과 데이터 대기 해소를 구분합니다.

## 비활성화와 외부 중단

- 다른 앱으로 전환하거나 화면을 잠그면 재생을 일시정지합니다. 백그라운드에서 계속 재생하지 않습니다.
- 전화 등으로 재생이 중단되면 자동으로 재개하지 않습니다.
- 이어폰 연결이 끊기면 일시정지해 스피커로 갑자기 재생되지 않게 합니다.
- 라디오 화면이 유지되는 동안 선택과 재생 위치를 보존합니다. 복귀 후 사용자가 재생을 요청하면 이어 듣습니다.
- 오디오 준비 중에도 앱 비활성화·오디오 중단·이어폰 연결 해제가 발생하면 이전 재생 요청을 실행하지 않습니다. 준비 완료나 다시 활성화되는 것만으로 자동 재생하지 않습니다.
- 상세 복귀는 위 일시정지와 구분합니다. 재생을 중지하고 위치를 초기화하며, 새 진입에서는 이전 선택과 위치를 복원하지 않습니다.

## 제공 범위

재생·일시정지와 진행 표시를 제공합니다. 구간 탐색·배속·자동 연속 재생·백그라운드 재생·대사 생성은 이번 범위에 포함하지 않습니다. 원격 URL의 접속 성공이나 HEAD 응답만으로 오디오 재생 성공을 보장하지 않습니다.

## 검증 경계와 후속 작업

ViewModel의 재생 제어를 확인할 RadioPlayback 대역과 테스트를 작성했습니다. 대역은 명령만 기록하고 테스트에서 상태를 공급하며 재생 정책을 대신 수행하지 않습니다. ViewModel 테스트가 통과했습니다.

ViewModel의 재생 제어는 RadioPlayback 대역으로 검증하고, 실제 RadioPlayback 구현의 상태 전환·교신 교체·늦은 이벤트 차단은 하위 오디오 연동 대역으로 검증합니다. 준비·재생, 일시정지·재개, 종료·다시 듣기, 실패·재시도, 교체·중지, 진행 정보 부재와 데이터 대기 해소를 확인합니다. 특히 준비·대기 중 중단 뒤 늦은 이벤트를 전달하여 자동 재개하지 않는지 확인합니다. 앱 비활성화·오디오 중단·이어폰 연결 해제 이벤트를 전달했을 때의 중단·위치 보존·자동 재개 차단은 자동 테스트 대상으로 삼고, 실제 시스템 이벤트와의 연결은 코드 검토로 확인합니다.

전화·이어폰 해제 등을 실제 기기에서 재현하는 검증은 필수 범위에서 제외합니다. 외부 개입 시 중단해야 한다는 동작 요구는 유지하며, 코드 검토나 대역 테스트를 실제 시스템 이벤트 재현 완료로 표시하지 않습니다. 원격 오디오의 실제 소리 출력·기본 재생 동작 확인과 이벤트 대역 검증도 구분해 기록합니다.

공개 상태·동작의 의미, 객체 수명과 정보 부재 시 표시는 합의했습니다. RadioPlayback 공개 선언은 Swift 파일에, RadioAudioTransport 선언도 Swift 파일에 옮겼으며 작업 구분은 이 문서를 따릅니다. 연동 경계의 Swift 선언과 [명령·이벤트 대역](../../../RadioLapTests/DriverRadio/TestDoubles/RadioAudioTransportSpy.swift), [재생 정책 테스트](../../../RadioLapTests/DriverRadio/Playback/RadioPlaybackTests.swift)을 작성했습니다. RadioPlayer(transport:)를 구현하고 RadioPlayback 계약으로 테스트해 통과했습니다. 재생 상태 관찰 전달도 ViewModel 테스트에서 확인했습니다. AVPlayerRadioAudioTransport의 상태·진행·종료·실패 이벤트 변환과 준비 교체·중지 시 관찰 및 오디오 정리를 구현했습니다. 최소 지원 버전인 iOS 27의 AVAudioSession.didBecomeInactiveNotification과 출력 경로 변경의 oldDeviceUnavailable을 interrupted로 전달하며 재개 권고로 재생하지 않습니다. 이 연결은 SDK 선언과 코드로 검토했고, 시뮬레이터 화면에서 원격 오디오의 재생·진행·일시정지·이어 듣기·종료와 앱 전환 후 자동 재개 방지를 확인했습니다. 실제 소리의 청취·중지는 사용자가 확인했습니다. 전화·이어폰 해제 재현은 필수 검증에서 제외한 범위로 유지합니다.
