# 드라이버 라디오 완료기준

[기능 목적](../README.md), [작업 범위](../AGENTS.md), [Repository 계약](RepositoryContract.md), [UseCase 계약](UseCaseContract.md), [화면 계약](PresentationState.md), [재생 계약](PlaybackContract.md)을 바탕으로 사용자 경험을 성립시키는 조건을 정의합니다. 기준의 합의와 실제 충족 여부를 구분하며 코드·테스트의 존재만으로 완료로 판단하지 않습니다.

## 검증 경계와 현재 상태

Repository·UseCase·ViewModel·재생 정책의 자동 테스트가 통과했습니다. 아래 영역 중 대역으로 확인한 동작과 실제 화면·오디오 연동을 구분합니다. AVPlayer·시스템 이벤트 연결을 코드로 검토하고 View·Component를 연결했습니다. 시뮬레이터에서 정상·빈 라디오, 선택·상황과 근거, 재생 상태·진행·제어, 앱 전환과 상세 복귀·재진입을 확인했습니다. 실제 소리 청취·중지, 화면 예외 상태·시간대 변경과 상세 스크롤 보존은 사용자가 확인했습니다.

| 영역 | 검증 방법 |
| --- | --- |
| 요청·취소 | UseCase·Repository 대역으로 요청 입력, 독립 상태, 취소와 늦은 응답 처리 확인 |
| 데이터 처리 | Repository는 JSON 자료로 해석·선별·실패 확인, UseCase는 Domain 자료로 정리·충돌 확인 |
| 상황 연결 | Domain 입력과 결과로 시각 경계·부재·충돌·순서 독립성 확인 |
| 표시·선택 | ViewModel의 상태·이벤트는 대역 테스트, 안내·배치·시간대·선택은 직접 화면 확인 |
| 재생·중단 | ViewModel 제어는 RadioPlayback 대역, 실제 재생 정책은 하위 오디오 연동 대역으로 검증. 시스템 이벤트 연결은 코드 검토, 기본 오디오 재생은 직접 확인 |
| 복귀·재진입 | 수명·늦은 이벤트는 대역 테스트와 코드 검토, 상세 복귀·스크롤 보존은 직접 화면 확인 |

전화·이어폰 해제 등의 실기기 재현은 필수 검증에서 제외합니다. 외부 개입 시 중단해야 한다는 동작 요구는 유지하며, 대역 테스트와 코드 검토를 실제 시스템 이벤트 재현 완료로 기록하지 않습니다. 검증 결과에는 수행한 방법과 확인하지 못한 범위를 구분합니다.

### 합의한 테스트 범위

- Repository: JSON 입력으로 요청 드라이버 선택, 빈 결과·미지원·읽기 실패 구분, 파일 전체와 선택 후 검증 경계, 필수·선택 값 해석, 중복·불완전 값 보존, 조회 독립성과 취소를 확인한다. 네트워크·오디오 접속과 반환 순서는 검증 대상으로 강제하지 않는다.
- UseCase: Repository 대역의 Domain 자료로 요청 전달·정리·충돌·조회 취소를 확인한다. 상황 연결은 시각 경계, 마지막 완료 랩, 독립 순위, 타이어 복합 사유 우선순위, nil과 빈 배열, 입력 순서 독립성과 추가 조회 없음을 확인한다. 동기 resolveContext에 취소 실패를 기대하지 않는다.
- ViewModel: UseCase·재생 대역으로 초기 입력과 조회 없음, load 중복 방지, 독립 조회·재시도·늦은 응답 차단, 선택·접기, context(for:)의 입력·결과 제공, 상태별 재생 명령, 재생 상태 변화의 공개 상태 반영, 비활성화·이탈을 확인한다. 상황 계산과 JSON 해석을 재검증하지 않는다.
- 재생 구현: 하위 오디오 명령·이벤트 경계를 대역으로 제어하여 실제 RadioPlayback 구현의 준비·재생·일시정지·재개·종료·실패·교체·중지·외부 개입과 진행 정보 부재를 확인한다. 대역에 자동 재개 방지나 늦은 이벤트 차단 정책을 구현해 검증 대상을 대신하지 않는다.

같은 검증을 여러 입력에 적용할 때는 매개변수 테스트로 묶고 내부 처리 순서를 불필요하게 강제하지 않는다. JSON은 수정 없이 읽는 자료로 구성하며 재사용 가능한 사례는 합쳐 파일명으로 구분한다. 테스트 작성·실행 완료를 의미하지 않는다.

## 1. 요청·취소

- 전달받은 Race와 RaceDriver를 보존하고 해당 세션·드라이버 식별자로 네 자료를 독립적으로 조회한다. 기본 정보를 다시 조회하지 않는다.
- 상황 자료가 늦거나 실패해도 준비된 라디오 목록을 표시하고 선택·재생할 수 있다.
- 정상 빈 결과·실패·취소를 구분하고 실패·취소된 자료만 재요청한다. 취소 후 자동 재시도하지 않는다.
- 재시도 중 다른 성공 자료와 선택·재생을 유지하며, 상황 자료가 준비되면 상황 정보만 갱신한다.
- 교체·취소된 요청의 늦은 성공·실패·취소는 현재 상태에 영향을 주지 않는다. 요청 유효성은 자료 종류마다 독립적으로 관리한다.
- 상세 복귀 시 요청을 취소·무효화하고 실제 종료를 기다리지 않고 이동한다.

## 2. 데이터 처리

- 지원하는 세션·드라이버의 자료만 반환하고 정상 빈 결과와 미지원 요청·읽기·해석 실패를 구분한다.
- 세션 전체 파일의 구조·식별자·세션을 검증한 뒤 요청 드라이버를 선택한다. 다른 드라이버의 비식별자 필드 오류는 현재 조회에 영향을 주지 않는다.
- 필수 필드 오류는 해당 조회 전체 실패로 처리한다. 선택 필드의 누락·null은 정보 부재로 보존하고 잘못된 값을 부재로 숨기거나 보정하지 않는다.
- Repository는 중복과 불완전 자료를 보존하고 UseCase가 정리한다. 날짜·URL·숫자 등 세부 허용 조건은 Repository 계약을 따르며 경계 사례는 해당 계약에서 도출한다.
- 라디오는 기록 시각과 URL이 같은 중복만 합치고 기록 시각순·동시각 URL순으로 제공한다.
- 같은 랩 번호의 값 충돌과 같은 시각의 순위 충돌은 해당 자료의 조회·정리 실패로 처리한다. 서로 다른 레코드의 값으로 누락을 보충하지 않는다.
- 스틴트는 컴파운드 앞뒤 공백과 동일 중복을 정리하되 불완전한 자료와 겹치는 범위를 보존한다. 특정 랩의 타이어 충돌을 조회 전체 실패로 바꾸지 않는다.

## 3. 상황 연결

- 라디오 기록 시각과 이미 조회·정리한 자료만 사용한다. 추가 조회나 현재 시각, 상세의 최종 결과로 상황을 보충하지 않는다.
- 랩은 시작 이상·종료 미만 구간으로 연결한다. 시간을 구성할 수 없는 랩은 연결에서 제외하며 공백·겹침을 임의 보정하지 않는다.
- 현재 랩이 없으면 기록 시각 이전 또는 같은 시각에 끝난 가장 최근 랩을 마지막 확인 정보로 제공한다. 현재 구간이 겹치거나 마지막 종료 시각이 같은 여러 랩은 충돌로 구분한다. 현재 구간 충돌을 마지막 확인 정보로 숨기지 않는다.
- 순위는 기록 시각 이전 또는 같은 시각의 최신 기록을 랩·타이어와 독립적으로 연결하고 근거 시각을 보존한다.
- 타이어는 결정된 랩을 포함하는 스틴트로 연결한다. 같은 컴파운드의 겹침은 허용하되 충돌·불완전 자료·정보 없음·자료 미준비는 UseCase 계약의 우선순위대로 구분한다.
- 현재 연결과 마지막 확인 정보, 정상 정보 부재와 자료 미준비를 구분한다. 같은 자료라면 배열 순서와 관계없이 같은 결과를 제공한다.

## 4. 표시·선택

- 모든 조회 상태에서 전달받은 레이스 이름·시즌과 드라이버 이름·팀을 유지한다. 팀 정보가 없으면 이를 표시하고 최종 순위를 상황 정보로 사용하지 않는다.
- 최초에는 교신을 모두 접어두고 자동 선택·재생하지 않는다. 랩 정보가 없어도 교신을 선택할 수 있다.
- 선택한 교신 하나만 펼친다. 접거나 다른 교신을 선택하면 기존 재생을 중지·초기화하고 새 교신은 재생 대기로 둔다.
- 확인 가능한 랩·순위·타이어를 독립적으로 표시하며 마지막 확인 정보·연결 불가·조회 중·실패·취소를 구분한다. 정상 빈 라디오는 공개 기록이 없다는 의미로 안내한다.
- 기록 시각과 실제 발화 시각이 다를 수 있음을 알리고 연결 근거를 펼쳐 확인할 수 있게 한다. 제공된 결과보다 구체적인 근거를 추정하지 않는다.
- 기록 시각은 기기 시간대로 초 단위까지 표시하고 적용 시간대와 날짜 변경을 구분한다. 시간대 변경은 표시만 바꾸며 순서·선택·재생·연결 결과를 유지한다.
- 오디오 길이·위치를 모르면 값을 추정하지 않는다. 정보가 준비되어도 표시만 갱신하고 재생을 다시 시작하지 않는다.

## 5. 재생·중단

- 사용자의 재생 요청으로만 오디오를 준비·재생하며 준비 중 중복 요청을 막는다.
- 최초 준비와 재생 중 데이터 대기는 preparing으로 표현한다. 데이터 대기 중 위치를 유지하고 재생 의도가 유지될 때만 이어 재생한다. 대기 중 일시정지·외부 개입·교신 변경·중지가 있으면 늦은 준비 완료로 자동 재생하지 않는다.
- 일시정지 후에는 같은 위치에서 이어 듣는다. 끝까지 재생하면 선택·상황 정보를 유지하고 다시 듣기는 처음부터 시작한다. 다음 교신을 자동 재생하지 않는다.
- 접기·교신 변경·상세 복귀 시 기존 오디오를 중지·초기화한다. 이전 오디오의 늦은 이벤트가 현재 상태를 바꾸거나 소리를 내지 않는다.
- 오디오 실패는 자료 조회 실패와 구분한다. 선택·상황 정보를 유지하고 재시도하면 같은 오디오를 처음부터 재생한다.
- 앱 비활성화·오디오 중단·이어폰 연결 해제 시 일시정지하고 자동 재개하지 않는다. 준비 중이었다면 준비가 끝나도 자동 재생하지 않는다.
- 같은 화면이 유지되는 중단에서는 위치를 보존한다. 상황 자료의 도착·재시도는 재생 상태나 위치를 초기화하지 않는다.

## 6. 복귀·재진입

- 라디오에서 상세로 돌아오면 기존 상세 결과와 스크롤 위치를 유지하고 재조회하지 않는다. 조회 취소·재생 중지는 위 요청·취소와 재생·중단 기준을 따른다.
- 같은 드라이버를 다시 선택하면 새 조회를 시작하며 이전 교신 선택·재생 위치를 복원하지 않는다.
- 라디오 화면마다 전용 재생 객체를 사용하고 화면이 다시 그려져도 ViewModel과 재생 객체를 새로 만들지 않는다.
- 이전 화면의 조회 응답이나 재생 이벤트가 새 화면에 반영되지 않는다.
- 앱 전환 후 같은 화면으로 돌아오면 선택·재생 위치를 유지한다. 상세에서 새로 진입하는 경우와 구분한다.

## 적용 범위

데모 JSON과 원격 오디오 URL로 확인합니다. 실제 데이터 API Provider·백그라운드 재생·대사 생성·구간 탐색·배속·자동 연속 재생·상세의 공개 라디오 개수 표시는 포함하지 않습니다. 목록 스크롤 보존과 기존 상세의 별도 미검증 상태를 자동 포함하지 않습니다. 세션 11388과 예시 값은 데모 공급 범위이며 제품의 선택 제한이 아닙니다.
