# 드라이버 라디오 작업 안내

## 문서 진입점

[README](README.md)의 경험과 이유를 먼저 확인하고, [Repository 계약](Docs/RepositoryContract.md) → [UseCase 계약](Docs/UseCaseContract.md) → [화면 계약](Docs/PresentationState.md) → [재생 계약](Docs/PlaybackContract.md) 순서로 검토합니다. 이후 [완료기준](Docs/CompletionCriteria.md)으로 책임별 검증 조건을 확인합니다. 목적 → 설계 → 완료기준 → 테스트 → 구현 순서로 진행하며 기존 구현이나 테스트 기대값을 요구사항의 근거로 삼지 않습니다.

## 합의한 범위와 현재 상태

상세에서 선택한 Race와 RaceDriver를 전달받아 레이스 이름·시즌과 드라이버 이름·팀을 표시합니다. 기본 정보는 다시 조회하지 않으며, 조회와 화면 식별에는 race.sessionID와 driver.driverNumber를 사용합니다. 최종 결과를 라디오 무렵의 상황으로 사용하지 않습니다.

현재 기능 범위는 OpenF1 API 기반 라디오·랩·순위·스틴트 조회와 응답의 오디오 URL을 이용한 실제 재생·일시정지입니다. 데모 JSON 공급은 테스트용으로 보존합니다. 백그라운드 재생, 대사 생성, 상세의 공개 라디오 개수 표시는 포함하지 않습니다.

데모 Provider·Interactor·ViewModel·재생 정책 객체와 AVPlayer 연동을 구현하고 테스트 타깃에 연결했습니다. Repository·UseCase·ViewModel·재생 정책 테스트와 기존 목록·상세 회귀 테스트, 시뮬레이터 대상 앱 빌드가 통과했습니다. View·Component와 상세 목적지를 연결했으며 상세에서 Race·RaceDriver를 보존해 전달합니다. 재생 객체는 각 라디오 화면 진입 시 한 번 생성합니다.

- 구현: DemoDriverRadioProvider·OpenF1DriverRadioProvider와 교신·랩·순위·스틴트 DTO, DriverRadioInteractor, DriverRadioViewModel, RadioPlayer, AVPlayerRadioAudioTransport. 재생 정책은 RadioAudioTransport 대역으로 확인하고 실제 시스템 이벤트 연결은 코드로 검토했습니다.
- 사용자 확인: 실제 소리의 청취·중지, 화면 예외 상태·시간대 변경, 실제 목적지 연결 후 상세 스크롤 보존을 확인했습니다.
- 직접 확인: 시뮬레이터에서 드라이버 3의 교신 목록·선택·상황·근거 펼치기·마지막 확인 랩 표시, 원격 오디오의 재생 상태·진행·일시정지·이어 듣기·종료, 앱 전환 후 자동 재개 방지, 다른 교신 선택 시 초기화와 상세 복귀·재진입을 확인했습니다. 드라이버 81의 공개 라디오 빈 결과도 확인했습니다.
- 검증 경계: 자동 테스트·시뮬레이터 확인과 사용자의 직접 확인을 구분합니다. 목록·상세의 기존 별도 미검증 항목은 이번 확인 범위에 포함하지 않습니다.

## 화면·재생 합의

상세 동작은 [화면 계약](Docs/PresentationState.md)과 [재생 계약](Docs/PlaybackContract.md)을 따릅니다. 자료별 조회 상태와 교신 선택·상황 연결 결과는 ViewModel, 오디오 상태·진행 위치·중단은 재생 담당 객체, 표시·이동·스크롤은 View가 담당합니다. Component는 의존성을 조립합니다.

최초에는 교신을 모두 접고 자동 선택·재생하지 않습니다. 선택한 하나만 펼치며 접기·다른 교신 선택·상세 복귀 시 재생을 중지하고 위치를 초기화합니다. 자료별 재시도는 다른 성공 자료와 선택·재생을 유지합니다. 앱 비활성화·외부 중단은 화면이 유지되는 동안 위치를 보존하되 자동 재개하지 않습니다.

시각은 기기 시간대로 표시하고 적용 시간대를 알립니다. 상황 연결 근거는 기존 RadioContext의 랩·순위 시각, 타이어 기준 랩과 연결 규칙, 연결 불가 사유까지 표시합니다. 개별 스틴트 범위 표시를 위해 Domain 모델을 확장하지 않습니다.

## 자료와 검증 경계

세션 11388 전체의 공개 원본 응답을 [Data/Fixtures](Data/Fixtures/)에 내용 수정 없이 저장했습니다. 파일 구성·지원 드라이버 22명과 공급 경계는 [Repository 계약](Docs/RepositoryContract.md#데모-공급과-공식-근거)을 따릅니다. 자료 저장과 앱 연결·조회 구현 완료는 구분합니다.

저장 자료는 라디오 32개, 랩 1,240개, 순위 기록 396개, 스틴트 47개입니다. 라디오가 있는 드라이버는 8명이며 14명은 정상 빈 결과 후보입니다. 랩 소요 시간에는 null 4개가 있습니다. JSON 배열·객체 구조와 세션·드라이버 범위를 확인했으나 모든 계약 검증이 완료된 것은 아닙니다.

드라이버 3의 라디오 세 개는 조사 시 합의한 규칙으로 랩 구간에 연결되고, 마지막 교신은 마지막 완료 랩 이후 정보로 구분할 수 있었습니다. 해당 네 오디오 URL은 HEAD 응답을 확인했고 이후 첫 교신의 재생 상태·진행·제어를 시뮬레이터 화면에서 확인했습니다. 전체 32개 URL을 검증한 것은 아닙니다. 이 표본의 값·필드 존재·선택 범위를 제품 요구사항으로 고정하지 않습니다. 정상·빈 결과는 데모로, 오류·충돌·취소는 별도 테스트 자료와 대역으로 확인합니다.

기존 로컬 HTML 직접 열기는 브라우저 정책의 파일 접근 제한으로 확인하지 못했습니다. 이후 2026-10-27 GitHub Pages에 게시된 와이어프레임을 Safari에서 열어 싱가포르 GP → Max Verstappen 진입과 41랩 라디오 카드 펼치기, 연결된 랩·순위·타이어 표시를 확인했습니다. 와이어프레임의 재생·전사 모형 동작과 나머지 예외 상태는 이번 확인에 포함하지 않았습니다. 화면 검토 시 [와이어프레임 안내](../../docs/WIREFRAMES.md)와 [게시된 와이어프레임](https://gen-com.github.io/RadioLap/radio-lap.html)을 확인합니다. 와이어프레임의 상호작용 확인과 실제 앱의 검증 결과를 구분합니다.

목록·상세의 미검증 항목은 이번 범위에 자동 포함하지 않습니다. 기존 기능 변경이 필요하면 연결에 필요한 이유와 범위를 별도로 제안합니다. 외부 개입 시 중단은 필수 동작으로 유지합니다. 이벤트 대역 테스트와 시스템 이벤트 연결 코드 검토로 확인하며 전화·이어폰 해제 등의 실기기 재현은 필수 검증에서 제외합니다. 실제로 확인하지 않은 동작을 검증 완료로 표시하지 않습니다.

## 합의와 다음 작업

- Repository의 입력 해석·실패·취소 기준과 데모 지원 범위·파일 구성·미지원 요청 처리는 합의했습니다. 합의한 완료기준과 테스트를 바탕으로 구현했습니다.
- Domain의 경계 처리, resolveContext 입력과 RadioContext의 항목별 결과·타이어 복합 사유 우선순위, URL 비교·정렬과 교신 식별은 합의했습니다. 별도 RadioContextResolver 없이 Interactor에서 수행하며, 결과 열거형과 RadioRecordID의 공개 선언은 UseCase 계약에 반영했습니다.
- 화면·재생의 공개 상태·동작 의미, 화면별 전용 재생 객체 수명, 팀 정보 부재와 진행 정보 미제공 시 표시를 계약에 반영했습니다. RadioLoadState·DriverRadioPresentation·RadioPlayback의 공개 선언과 초기화 입력을 계약에 반영했습니다. 화면·재생 공개 선언과 ViewModel·재생 정책 구현을 테스트 타깃에서 컴파일하고 검증했습니다. AVPlayer 연동과 작은 명령·이벤트 경계 하나를 사용하며 재생 정책은 RadioPlayback 구현에 둡니다. RadioAudioTransport의 준비·재생·일시정지·중지 명령과 준비 요청별 이벤트 콜백을 재생 계약에 구체화했습니다. 연동 경계 선언과 대역·재생 정책 테스트를 작성하고 재생 객체의 관찰 상태 전달은 ViewModel 테스트로 확인했습니다. AVPlayer 상태·진행·종료·실패와 AVAudioSession의 비활성화·출력 장치 해제 알림 변환을 구현하고 코드로 검토했습니다.
- Repository 리뷰 사항은 파일 전체의 구조·식별자·세션 검증, 요청 드라이버 선택, 선택 자료의 필드 검증으로 정리해 반영했습니다. 다른 드라이버의 비식별자 필드 오류는 현재 조회에 영향을 주지 않습니다.
- [테스트 디렉토리](../../RadioLapTests/DriverRadio/)에서 Repository는 JSON 입력과 반환 모델·오류, UseCase는 Domain 자료의 정리·상황 연결, ViewModel은 독립 조회·재시도·선택·상황 계산 위임·재생 제어·상태 관찰·이탈·재진입을 다룹니다. 재시도 대기 중 보존과 재생 요청의 자료 재조회 방지도 포함합니다. 재생 대역은 명령만 기록하며 테스트에서 상태를 공급합니다.
- 재생 정책 테스트는 RadioPlayer(transport:) 구현을 RadioPlayback 계약으로 사용합니다. 대역은 명령을 기록하고 이전 준비 콜백에도 이벤트를 전달하며 최신 작업 판정·자동 재개 방지 정책을 대신하지 않습니다. View·Component와 상세 목적지 연결을 구현했습니다. 화면 코드 리뷰와 목적지 제네릭 정리를 마쳤고, 남아 있던 직접 검증 항목은 사용자가 확인했습니다.
- preparing은 최초 준비와 재생 중 데이터 대기를 함께 표현합니다. 위치를 유지하며 재생 의도가 유지될 때만 이어 재생하고, 중단·교신 변경 뒤 늦은 준비 완료로 자동 재개하지 않습니다. 실제 재생 정책은 하위 오디오 연동 대역으로 검증하며 대역 자체를 검증 대상으로 삼지 않습니다.

## 작업 규칙

[아키텍처](../../docs/ARCHITECTURE.md), [코딩](../../docs/CODING_CONVENTIONS.md), [문서화](../../docs/DOCUMENTATION.md), [테스트](../../docs/TESTING.md), [커밋](../../docs/COMMIT_CONVENTIONS.md) 규칙을 따릅니다. 기능별 Component에서 조립하고 진입 View에 직접 주입하며, 외부 의존성이 필요할 때만 Dependency를 둡니다. Race·RaceDriver의 별도 진입 모델 복제나 공통 모델 계층 신설은 현재 범위가 아닙니다.

JSON은 수정 없이 사용할 입력으로 구성하고 재사용 가능한 자료는 합쳐 파일명으로 구분합니다. 불필요한 후보·최종 모델 복제, 하위 타입·중간 계층·중복 검증을 피합니다. README는 경험과 이유, 계약은 책임·입출력·보장 조건을 담고 별도 Context·구현 설명·검증 설명 문서는 만들지 않습니다.

파일 변경·빌드·테스트·설치·커밋·외부 변경 전에 구체적인 범위와 검증 방법을 제시하고 명시적 승인을 받습니다. 방향 합의나 질문에 대한 답을 편집 승인으로 간주하지 않습니다. 문서 추가 시 앱 타깃 제외 설정을 맞추며, 미실행 검증을 완료로 표시하지 않습니다.
