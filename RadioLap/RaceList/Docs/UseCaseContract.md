# 레이스 목록 UseCase 계약

[기능 목적](../README.md)과 [현재 작업 범위](../AGENTS.md#현재-작업-범위)를 바탕으로, 목록에 제공할 레이스의 선별·정제·최신순 정렬을 정의합니다. 데이터 공급 방식은 [Repository 계약](RepositoryContract.md)에 위임합니다.

## 책임과 입출력

추상화는 `RaceListUseCase`, 구현은 `RaceListInteractor`로 정의하며 둘 다 Domain에 둡니다. Interactor는 Repository 계약을 주입받고, 후보를 조회해 아래 규칙을 수행합니다. 외부 응답을 직접 해석하거나 화면 상태를 만들지 않습니다.

```swift
protocol RaceListUseCase: Sendable {
    func fetchRaces(
        year: Int,
        endedBefore: Date
    ) async throws -> [Race]
}
```

| 항목 | 의미 |
| --- | --- |
| `year` | 조회할 시즌. Repository의 `fetchRaceCandidates(year:)`에 전달하고 최종 반환 대상도 이 시즌인지 확인합니다. |
| `endedBefore` | 종료 여부를 판단할 절대 시각. 호출자가 조회 시작 시점의 시각을 전달하며 UseCase는 현재 시각을 별도로 읽지 않습니다. |
| `[Race]` | 선별·정제·중복 처리를 마치고 최신순으로 정렬한 레이스 목록입니다. |
| 빈 배열 | 후보가 없거나 선별·정제 후 남은 결승이 없는 정상 결과입니다. |

반환 모델은 다음 의미를 갖습니다.

```swift
struct Race: Identifiable, Equatable, Sendable {
    let sessionID: Int
    let season: Int
    let name: String
    let startsAt: Date
    let location: String?

    var id: Int { sessionID }
}
```

`sessionID`는 결승 식별자, `season`은 검증된 세션의 시즌, `name`은 대회 이름, `startsAt`은 결승 시작 절대 시각입니다. `location`이 nil이면 장소 정보가 없다는 뜻입니다. 날짜 표시 문자열·화면 상태는 포함하지 않습니다. `season`은 요청 시즌 및 연결 대회와 일치함을 확인한 세션의 값을 보존합니다. 날짜에서 계산하거나 후보의 누락을 요청 시즌으로 보충하지 않습니다. 목록에서 선택한 `Race` 전체를 상세에 전달하며 상세는 이 기본 정보를 다시 조회하지 않습니다.

## 입력 후보 모델

Repository가 제공하는 `RaceCandidate`의 확정된 속성과 타입은 [후보 모델 계약](RepositoryContract.md#후보-모델의-의미)을 따릅니다. 외부 DTO를 직접 입력으로 사용하지 않습니다.

- `linkedMeetings`가 빈 배열이면 연결할 대회가 없는 후보입니다. 여러 항목이면 동일한 중복이나 충돌 정보가 보존된 상태이므로 임의로 첫 항목만 선택하지 않습니다.
- `kind == .race`는 결승, `.other`는 결승이 아님이 확인된 세션입니다. nil은 판별 불가이며 other와 구분합니다.
- 이름·시각의 nil은 해당 정보를 사용할 수 없다는 뜻으로, 아래 항목 제외 정책을 적용합니다. 빈 문자열·공백 이름과 잘못된 시각 관계도 후보에 보존되어 있습니다.
- 식별자·시즌·종류·취소 여부의 nil은 불확실성을 표현합니다. 임의로 기본값을 넣지 않고 아래 불완전 후보 정책을 적용합니다.
- 유효한 후보를 `Race`로 반환할 때 식별자·시즌·이름·시작 시각은 필수 값이 되고 장소만 Optional로 유지됩니다.

## 선별과 정제

### 필수 정보와 대회 연결

- `sessionID`가 nil인 후보는 제외합니다. 다른 후보와 같은 결승이라고 추정하지 않습니다.
- 세션의 `season`·`kind`·`isCancelled`가 nil이면 해당 후보로 레이스를 구성하지 않습니다. 요청 시즌이나 false 등으로 보충하지 않습니다.
- 연결 대회의 이름이 nil·빈 문자열·공백뿐이거나 `season`·`isCancelled`가 nil이면 해당 대회 정보로 레이스를 구성하지 않습니다.
- 대회와 세션의 시즌이 다르면 해당 연결 정보를 사용할 수 없는 것으로 처리합니다.
- `linkedMeetings`가 비어 있거나 사용할 수 있는 대회 정보가 없으면 해당 후보를 제외합니다. 다른 유효한 연결 정보가 있으면 검토하되, 아래 충돌 검사를 먼저 적용합니다.
- 시작·종료 시각이 nil이거나 종료 시각이 시작 시각보다 이르거나 같으면 해당 후보를 제외합니다.
- 서로 다른 불완전 후보의 이름·시각·시즌·취소 여부를 짜깁기해 레이스를 구성하지 않습니다. 하나의 후보와 그 후보에 연결된 유효한 대회 정보로 구성할 수 있어야 합니다.

### 표시할 결승

- 유효한 후보 중 요청한 시즌의 결승만 포함합니다. 다른 시즌, `.other`, 취소된 대회·세션은 제외합니다.
- 종료 시각이 `endedBefore`보다 이른 결승만 포함합니다. 같거나 늦으면 제외합니다.
- 결과 확정·라디오 준비 여부는 포함 조건으로 사용하지 않습니다. 해당 데이터의 조회나 준비 여부 판단도 수행하지 않습니다.
- 장소가 없어도 결승을 유지합니다.
- 한 결승의 제외 때문에 다른 식별자의 정상 결승이 누락되거나 값이 변경되지 않습니다.

## 중복과 정보 충돌

같은 `sessionID`의 후보들을 모아, 불완전 후보 제거와 표시 대상 선별보다 먼저 확인 가능한 값의 충돌을 검사합니다. 입력 순서에 따라 임의의 후보를 선택하지 않습니다.

### 누락과 명시적 충돌

- nil과 빈 문자열·공백뿐인 이름은 정보 부족이며 다른 값과의 명시적 충돌로 보지 않습니다.
- 같은 식별자의 이름·시작 시각·종료 시각에 서로 다른 확인 가능한 값이 있으면 해당 결승 전체를 제외합니다.
- 세션 시즌·종류·취소 여부 또는 연결된 대회의 시즌·취소 여부가 같은 속성 내에서 서로 다르면 해당 결승 전체를 제외합니다. 결승과 다른 종류, 취소와 비취소, 서로 다른 시즌 중 유리한 후보만 남기지 않습니다.
- 대회 시즌과 세션 시즌의 불일치는 연결 유효성 문제이며, 같은 속성의 중복 값 충돌과 구분합니다.
- 불완전 후보라도 확인 가능한 충돌 값은 검사에 포함합니다. 예를 들어 이름이 없는 취소 후보와 이름이 있는 비취소 후보가 함께 있으면 취소 여부 충돌로 결승 전체를 제외합니다.
- 불완전 후보에 충돌 값이 없다면 해당 후보만 제외하고 다른 정상 후보를 유지합니다. 이름만 없고 나머지 값이 일치하는 후보 때문에 정상 결승을 제외하지 않습니다.
- 동일한 중복은 하나로 합칩니다. 이름이 같아도 식별자가 다르면 별개의 결승입니다.

### 장소만 다른 경우

장소는 선택 정보이므로 충돌해도 결승을 제외하지 않습니다.

| 같은 식별자의 장소 정보 | 반환 장소 |
| --- | --- |
| 모두 없음 | nil |
| 확인 가능한 장소가 모두 같음 | 해당 장소 |
| 일부는 없고 나머지는 같은 장소 | 확인된 장소 |
| 서로 다른 장소가 존재 | nil |

충돌하는 장소 중 하나를 임의로 선택하지 않습니다. 이 결과를 어떻게 안내할지는 [화면 상태 계약](PresentationState.md#화면-표시와-이동)의 책임입니다.

## 처리 순서와 반환 보장

1. 식별자가 없는 후보를 제외합니다.
2. 같은 식별자의 후보와 각 후보에 연결된 대회 정보를 모읍니다. 원래의 후보·대회 연결 관계는 유지합니다.
3. 확인 가능한 값의 충돌을 검사합니다. 이름·시각·조회 자격 충돌은 결승 전체를 제외하고, 장소 충돌은 반환 장소만 nil로 결정합니다.
4. 불완전하거나 연결이 유효하지 않은 후보를 제외합니다. 서로 다른 후보의 필수 값을 합쳐 새 레이스를 만들지 않습니다.
5. 남은 후보에 요청 시즌·결승 종류·취소 여부·종료 시각 조건을 적용합니다.
6. 동일한 결승은 하나로 반환하고, `startsAt` 내림차순·동률이면 `sessionID` 오름차순으로 정렬합니다.

위 순서는 결과를 결정하는 규칙의 우선순위입니다. 반복문이나 함수 호출의 내부 순서를 강제하지 않습니다. 후보 목록과 `linkedMeetings`의 입력 순서를 바꿔도 최종 결과는 같아야 합니다.

반환 목록의 `sessionID`는 중복되지 않습니다. 제외할 항목만 있으면 정상 빈 배열을 반환합니다. 반환 순서의 화면 반영은 [화면 상태 계약](PresentationState.md#조회와-결과-반영)을 따릅니다.

## 실패와 취소

- Repository의 전체 실패를 빈 배열로 바꾸거나 숨기지 않고 전달합니다.
- 합의한 항목 제외 사유는 전체 실패로 처리하지 않습니다. 모두 제외되면 빈 배열입니다.
- 호출 작업의 취소를 Repository 작업에 전파하고 선별·정제·정렬 작업도 취소에 협조합니다. 취소는 `CancellationError`로 전달하며 정상 빈 결과나 일반 조회 실패로 바꾸지 않습니다.
- 하위 작업의 즉시 종료를 보장하지는 않습니다. 늦은 응답의 화면 반영 여부와 최신 요청 관리는 [화면 상태 계약](PresentationState.md#취소와-늦은-응답)에 위임합니다.

## 호출 관계와 검증 경계

```text
ViewModel → RaceListUseCase.fetchRaces(year, endedBefore)
                 ↓ RaceListInteractor
            RaceListRepository.fetchRaceCandidates(year)
                 ↓ 후보 반환
            선별·정제·중복 처리·최신순 정렬
                 ↓ [Race]
ViewModel ← 반환 순서를 유지해 화면 상태 결정
```

- Repository 테스트는 요청·외부 응답 해석·연결·후보 변환과 전체 실패·취소를 확인합니다.
- UseCase 테스트는 Repository 테스트 대역이 제공하는 후보로 선별·정제·정렬·빈 결과·실패 전달·취소를 확인합니다.
- ViewModel 테스트는 UseCase 테스트 대역으로 조회·재시도·취소·최신 요청 관리와 화면 상태를 확인합니다.

구체적인 수용 기준은 [완료기준](CompletionCriteria.md)을 따릅니다.
