# 레이스 목록 완료기준

[기능 목적](../README.md), [현재 작업 범위](../AGENTS.md#현재-작업-범위), [Repository 계약](RepositoryContract.md)과 [UseCase 계약](UseCaseContract.md)을 바탕으로, 기능이 올바르게 동작하기 위해 지켜야 할 사항을 정의합니다.
기준 충족 여부는 실제 검증 결과로 판단하며, 구현이나 테스트 코드의 존재만으로 완료로 판단하지 않습니다.

## 검증 경계

기능의 완료기준은 아래 세 영역으로 유지하며, 각 책임의 입출력에서 검증합니다.

| 대상 | 검증 책임 |
| --- | --- |
| Repository | 시즌을 사용한 요청, 외부 응답 해석·대회 연결·후보 변환, 누락·중복 보존, 전체 실패·취소 전달. 반환 순서는 보장하지 않는다. |
| UseCase | 후보 조회, 결승 선별·항목 제외·중복 처리·최신순 정렬, 정상 빈 결과, 실패 전달과 취소 전파. |
| Presentation | 최초 조회·재시도·취소·최신 요청 관리, UseCase 반환 순서를 유지한 상태 전환, 화면 표시·선택·복귀. |

Repository 테스트의 기대값은 정제 전 후보이며, 정제된 레이스와 정렬 순서는 UseCase 테스트에서 확인합니다. ViewModel은 후보를 다시 정제하거나 반환 순서를 바꾸지 않습니다.

## 1. 목록 데이터 요청

### 조회 시작과 재시도
- 목록 화면에 최초 진입하면 2026 시즌의 레이스 목록을 요청한다.
- 요청마다 조회 시작 시점의 현재 시각을 종료 판단 기준으로 전달한다.
- 조회에 실패한 뒤 사용자가 재시도하면 새로운 기준 시각으로 다시 요청한다.
- 목록에서는 드라이버 결과나 라디오 데이터를 미리 요청하지 않는다.

### 후보 데이터 요청
- UseCase는 요청받은 시즌을 Repository에 전달한다. 종료 판단 기준 시각은 Repository에 전달하지 않고 UseCase에서 사용한다.
- Repository는 요청 범위의 외부 자료를 도메인 후보로 제공한다. 이름·시각 누락, 대회 연결 누락이나 중복을 목록 제공 정책으로 제거하지 않는다.
- Repository가 빈 후보 목록을 반환하면 UseCase도 정상 빈 목록을 반환한다.

### 조회 취소
- 조회 중 목록 화면을 떠나면 진행 중인 요청의 취소를 요청한다.
- 취소한 요청이 실제로 종료될 때까지 화면 이동이나 다음 조회를 기다리게 하지 않는다.
- UseCase는 호출 작업의 취소를 Repository에 전파하고 정제 작업도 취소에 협조한다. Repository와 UseCase는 취소를 `CancellationError`로 전달한다.
- 조회 취소를 조회 실패로 안내하지 않는다.
- 진행 중인 조회가 없을 때 취소하더라도 기존 목록·빈 결과·실패 상태를 유지한다.

### 연속 요청과 응답 순서
- 조회 중 새 요청을 시작하면 이전 요청의 취소를 요청한다.
- 이전 요청이 취소를 무시하거나 응답이 늦어져도 새 요청을 진행할 수 있다.
- 응답 도착 순서와 관계없이 가장 최근에 시작했으며 취소되지 않은 요청의 결과만 반영한다.
- 취소되거나 새 요청으로 대체된 요청의 성공·실패·취소 결과는 현재 조회 상태를 변경하지 않는다.
- 이전 요청이 늦게 끝나더라도 현재 진행 중인 요청을 취소할 수 있다.

## 2. 받은 데이터 처리

### 표시할 결승 선별
- 요청한 시즌의 결승만 포함한다. 연습·예선·스프린트와 취소된 대회·세션은 제외한다.
- 종료 시각이 요청 시 전달한 기준 시각보다 이른 결승만 포함한다. 기준 시각과 같거나 늦으면 제외한다.
- 종료 판단에 별도의 현재 시각을 사용하지 않는다.
- 경기 결과 확정이나 라디오 준비 여부는 목록 포함 조건으로 사용하지 않는다. 해당 정보의 준비 여부는 다음 화면에서 다룬다.

### 대회 정보 연결과 값의 의미

Repository는 아래 기준으로 후보를 변환하고 UseCase는 확정된 값을 반환 레이스에 유지한다.

- 대회와 세션은 대회 식별자인 `meeting_key`로 연결한다. 응답 순서나 대회 이름으로 연결하지 않는다.
- 결승 식별자는 세션의 `session_key`, 대회 이름은 연결된 대회의 `meeting_name`을 사용한다.
- 레이스의 시작 시각은 대회 주말 시작일이 아닌 결승 세션의 시작 시각을 사용한다.
- 장소는 결승 세션의 장소 정보를 사용한다.
- 시차 표기가 달라도 같은 순간을 나타내면 같은 절대 시각으로 처리한다. 기기 시간대에 따라 조회 대상이나 시각 값이 달라지지 않는다.

### 정보가 부족하거나 잘못된 항목

Repository가 누락·해석 불가·연결 누락을 표현한 후보를 제공하면 UseCase의 결과를 확인한다.

- 식별자가 nil인 후보는 제외하며 다른 식별자의 정상 결승은 유지한다.
- 세션의 시즌·종류·취소 여부 중 하나가 nil이면 해당 후보를 제외한다. 요청 시즌이나 false로 보충하지 않는다.
- 연결 대회의 이름이 nil·빈 문자열·공백뿐이거나 시즌·취소 여부가 nil이면 해당 대회 정보로 레이스를 구성하지 않는다.
- 대회와 세션의 시즌이 다르면 해당 연결 정보로 레이스를 구성하지 않는다. 사용할 수 있는 연결 정보가 없으면 후보를 제외한다.
- 연결 대회 일부가 불완전하더라도 명시적 충돌이 없고 같은 후보에 다른 유효한 대회 정보가 있으면 그 정보로 결승을 유지한다.
- 시작·종료 시각 각각이 nil인 경우와 종료 시각이 시작 시각보다 이르거나 같은 경우에 해당 후보를 제외한다.
- 필수 정보가 서로 다르게 빠진 후보들을 합쳐야만 완성되는 결승은 반환하지 않는다.
- 제외 대상 때문에 다른 식별자의 정상 결승이 누락되거나 값이 변경되지 않는다.

### 중복과 충돌의 우선순위

UseCase의 입력 순서를 바꾸고 정상 결승을 함께 제공해, 충돌한 결승만 제외되는지 확인한다.

- 동일한 결승 데이터가 중복되면 하나로 합친다. 이름이 같아도 식별자가 다르면 별개의 결승이다.
- 같은 결승 식별자의 이름·시작·종료 시각에 서로 다른 확인 가능한 값이 있으면 해당 결승 전체를 제외한다.
- 같은 결승 식별자의 세션 시즌·종류·취소 여부 또는 연결된 대회의 시즌·취소 여부가 같은 속성 내에서 충돌하면 해당 결승 전체를 제외한다.
- 취소 여부·종류·시즌으로 먼저 걸러내면 충돌이 사라지는 입력에서도 해당 결승을 제외한다. 선별보다 충돌 판단이 우선한다.
- 이름이 없는 취소 후보와 완전한 비취소 후보가 함께 있으면 결승 전체를 제외한다. 불완전 후보의 확인 가능한 충돌 값도 무시하지 않는다.
- 이름만 없고 나머지 확인 가능한 값이 같은 후보가 정상 후보와 함께 있으면 정상 결승을 유지한다. nil·빈 이름·공백 이름 자체를 충돌 값으로 보지 않는다.
- 세션 후보와 연결된 대회 배열 각각의 순서를 바꿔도 최종 결과는 같다.
- 모든 후보가 제외되면 정상 빈 결과가 되며, 다른 식별자의 정상 결승을 함께 넣으면 그 결승은 보존한다.

### 장소 정보

- Repository는 장소 누락·null·빈 문자열을 nil로 정규화한다.
- UseCase는 장소가 없어도 결승을 유지한다.
- 같은 식별자의 장소가 모두 없으면 nil, 확인된 장소가 모두 같으면 해당 장소를 반환한다.
- 일부 장소가 없고 나머지가 같은 장소이면 확인된 장소를 반환한다.
- 서로 다른 장소가 있으면 결승은 하나로 유지하고 장소만 nil로 반환한다. 입력 순서에 따라 장소가 달라지지 않는다.

### 반환 정보

- 반환 Race는 검증된 세션의 시즌을 season에 보존한다. 날짜에서 연도를 계산하거나 누락된 시즌을 요청값으로 보충하지 않는다.

### 정렬

UseCase의 반환 목록은 다음 순서를 보장한다.

- 결승 시작 시각이 최근인 순서로 정렬한다.
- 시작 시각이 같으면 결승 식별자 오름차순으로 정렬해 표시 순서를 일정하게 유지한다.

### 빈 결과와 조회 실패
- 조회가 정상적으로 끝났지만 조건에 맞는 결승이 없으면 정상 빈 결과로 처리한다.
- 항목 제외 정책에 따라 모든 결승이 제외된 경우도 정상 빈 결과로 처리한다.
- HTTP 오류·통신 실패 또는 응답 전체를 읽거나 해석할 수 없는 경우는 조회 실패로 처리한다.
- 파일을 데이터 출처로 사용하는 경우, 파일·리소스 누락이나 읽기 실패도 조회 실패로 처리한다.
- Repository의 전체 실패를 UseCase가 숨기거나 빈 배열로 바꾸지 않고 전달한다.
- 조회 전체의 실패를 빈 결과로 바꾸지 않으며, 항목 단위의 문제로 정상 목록 전체를 실패시키지 않는다.

## 3. 화면 표시와 선택

### 조회 상태 표시
- 조회 중에는 진행 표시와 “레이스를 불러오는 중입니다” 안내를 보여준다.
- 표시할 결승이 있으면 정렬된 목록을 보여주고 레이스를 선택할 수 있게 한다.
- 정상 빈 결과이면 “2026 시즌에 조회할 수 있는 종료된 결승이 없습니다”를 표시한다.
- 조회에 실패하면 “레이스 목록을 불러오지 못했습니다. 다시 시도해주세요.”라는 안내와 “다시 시도” 버튼을 보여준다.
- “다시 시도”를 선택하면 목록을 다시 요청한다.
- 현재 조회의 성공·빈 결과·실패가 반영되거나 해당 조회를 취소하면 진행 표시를 끝낸다. 이전 요청의 종료로 현재 진행 중인 조회의 표시를 끝내지 않는다.

### 레이스 정보 표시
- 각 레이스의 대회 이름, 결승 시작 날짜·시간, 장소를 표시한다.
- 날짜·시간은 사용자 기기의 시간대로 표시한다. 날짜 경계와 서머타임을 포함해 해당 시각의 시간대 규칙을 적용한다.
- 기기 시간대 변경 후 다시 표시할 때는 변경된 시간대를 적용한다. 이 때문에 목록을 추가 조회하거나 레이스의 절대 시각·정렬 순서를 바꾸지 않는다.
- 장소 정보가 없으면 “장소 정보 없음”으로 표시한다. 장소를 임의로 추측하지 않는다.

### 레이스 선택과 목록 복귀
- 레이스를 선택하면 season을 포함한 선택 Race 전체를 상세 화면에 전달한다. 상세 기본 정보를 위해 목록에서 추가 조회하지 않는다.
- 상세 화면에서 목록으로 돌아오면 재조회하지 않고 기존 목록과 보던 스크롤 위치를 유지한다.

연도 선택, 페이지네이션, 사용자 조작에 의한 새로고침과 상세 화면 자체의 동작은 이 완료기준의 범위에 포함하지 않습니다.

### 계약과 검증 상태

후보 모델은 [Repository 계약](RepositoryContract.md#후보-모델의-의미), 정제 정책과 결과를 결정하는 우선순위는 [UseCase 계약](UseCaseContract.md#처리-순서와-반환-보장)을 따른다. 위 기준은 합의된 요구사항이며 구현이나 테스트 통과를 뜻하지 않는다. 내부 반복문·호출 순서 대신 해당 우선순위에 따른 반환 결과를 검증한다.
