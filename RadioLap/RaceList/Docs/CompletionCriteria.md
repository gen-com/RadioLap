# 레이스 목록 완료기준
[기능 문맥](Context.md), [Repository 계약](RepositoryContract.md), [화면 상태](PresentationState.md)에서 요구하는 동작을 완료기준으로 정의합니다. 구현과 테스트는 이 기준을 충족해야 하며, 테스트의 존재나 실행 결과로 기준을 정하지 않습니다.

## Repository와 Provider
| 분야 | 완료기준 |
| --- | --- |
| 조회 대상 | 요청한 시즌의 결승만 반환한다. 연습·예선·스프린트와 취소된 대회·세션은 제외한다. |
| 종료 판단 | 호출자가 전달한 endedBefore를 기준으로 API 종료 시각이 더 이른 세션만 반환한다. 같거나 늦으면 제외하며, Provider가 현재 시각을 별도로 읽어 판단하지 않는다. |
| 데이터 연결 | 응답 순서나 대회 이름에 의존하지 않고 meeting_key로 연결한다. 표시 대상에 필요한 대회가 없으면 오류를 전달한다. |
| 반환 값 | sessionID는 session_key, name은 meeting_name, startsAt은 결승 세션의 date_start, location은 세션의 location에 대응한다. 대회 주말 시작일을 결승 시작 시각으로 사용하지 않는다. |
| 시간 | 시차 표기가 달라도 같은 순간이면 같은 Date로 반환한다. 기기 시간대가 달라져도 조회 조건과 반환하는 절대 시각은 바뀌지 않으며, 시즌은 요청한 year를 따른다. |
| 장소 | 장소 누락·null·빈 문자열은 nil로 반환하고, 장소가 없다는 이유로 목록 전체를 실패시키지 않는다. |
| 중복 | 반환 목록의 sessionID는 중복되지 않는다. 동일한 중복은 합치고, 표시 여부나 표시 대상 내용이 충돌하면 오류를 전달한다. 이름이 같아도 식별자가 다르면 별개로 취급한다. |
| 데이터 오류 | 필수 필드·타입·날짜 해석 실패는 제외 대상에서도 오류로 전달한다. 표시 대상에 필요한 값의 유효성을 검증하며, 잘못된 대상 항목을 조용히 버리지 않는다. |
| 빈 결과 | 정상 조회했으나 조건에 맞는 결승이 없으면 빈 배열을 반환한다. 실패를 빈 배열로 바꾸지 않는다. |
| 취소 | 작업 취소는 CancellationError로 전달한다. |
| 책임 분리 | Repository는 화면 표시 문자열과 화면 상태를 만들지 않는다. 반환 순서는 보장하지 않으며 최신순 정렬은 ViewModel이 담당한다. |

### 데모 데이터
- 번들 또는 직접 전달한 파일 URL의 meetings.json·sessions.json을 읽고, 네트워크 접근 없이 동일한 조회 조건과 반환 계약을 충족한다.
- 파일·번들 리소스 누락과 파일 읽기 실패를 오류로 전달한다.
- 저장된 일정에도 전달받은 종료 기준을 적용한다. 스냅샷이라는 이유로 반환 대상이나 건수를 고정하지 않는다.

## 실제 API 연동
- 요청한 시즌의 meetings와 결승(session_name=Race) sessions를 조회하고 meeting_key로 연결한다. 레이스마다 추가 요청하지 않는다.
- HTTP 오류·통신 실패는 오류로 전달하고, 요청 취소는 CancellationError로 전달한다.
- 실제 Provider와 데모 Provider는 동일한 입력 데이터와 조회 조건에 대해 같은 반환 계약을 충족한다.

## ViewModel과 화면
ViewModel과 View의 완료 여부는 아래 책임별 기준으로 각각 판단한다.

### ViewModel
#### 공개 계약과 초기화
- 상태 타입과 ViewModel 프로토콜은 구체 구현과 분리한다. 프로토콜은 읽기 전용 state와 load·cancel을 제공하며, 상태 변경을 관찰할 수 있다.
- 상태는 MainActor 내부에서 변경하며 목록·로딩·오류를 별도 상태로 중복 관리하지 않는다. 목록은 content에만 보관한다.
- load와 cancel은 동기 메서드로, 조회 응답을 기다리지 않고 반환하며 오류를 외부로 던지지 않는다.
- 초기 상태는 idle이며 초기화만으로 Repository나 now를 호출하지 않는다.
- 주입받은 Repository를 사용하며 구체적인 Provider를 생성하거나 API 응답을 직접 처리하지 않는다.

#### 조회와 결과 반영
- 최초 조회·재시도·재조회는 모두 load를 사용한다. 모든 상태에서 호출할 수 있고, 호출하면 새 조회를 시작하며 즉시 loading으로 전환한다.
- 실행 전 취소 여부와 관계없이 load 호출마다 now를 한 번 읽는다. Repository를 호출할 때 year: 2026과 해당 호출에서 읽은 기준 시각을 endedBefore로 전달한다.
- 마지막 유효 요청의 결과를 다음과 같이 표현한다.

| 결과 | 완료기준 |
| --- | --- |
| 레이스 있음 | startsAt 내림차순, 동률은 sessionID 오름차순으로 정렬하여 content로 전환한다. |
| 빈 배열 | content([])가 아닌 empty로 전환한다. |
| 일반 오류 | “레이스 목록을 불러오지 못했습니다. 다시 시도해주세요.”라는 안내의 failed로 전환한다. |
| Repository의 CancellationError | 실패 안내 없이 idle로 전환한다. |

#### 취소와 늦은 응답
- 조회 중 load를 다시 호출하면 이전 요청을 취소한다. 이전 요청이 취소를 무시해도 그 종료를 기다리지 않고 새 조회를 시작할 수 있다.
- 응답 순서와 관계없이 취소된 요청의 성공·일반 오류·CancellationError는 현재 상태를 바꾸지 않는다. 이전 요청이 늦게 끝나도 현재 요청을 취소할 수 있다.
- 진행 중인 요청이 있을 때 cancel을 호출하면 취소를 전달하고, 요청의 종료를 기다리지 않고 즉시 idle로 전환한다. 진행 중인 요청이 없으면 현재 상태를 유지한다.
- 실행 전에 취소된 조회는 Repository를 호출하지 않는다.
- 호출 작업의 취소는 조회를 자동으로 취소하지 않는다. 이미 취소된 호출 작업에서도 load는 새 조회를 시작하며, 조회 취소는 명시적인 cancel로 전달한다.

### View
#### 조회 시점과 상태 표시
- 화면 진입 시 load를 호출하고, 화면이 사라질 때 cancel을 호출한다.
- loading에서는 “레이스를 불러오는 중입니다”와 진행 표시를 보여준다.
- content에서는 레이스 목록을 표시하고 선택할 수 있게 한다.
- empty에서는 “2026 시즌에 조회할 수 있는 종료된 결승이 없습니다”를 표시한다.
- failed에서는 상태의 안내 메시지와 “다시 시도” 버튼을 표시하고, 버튼 선택 시 load를 호출한다.

#### 화면 표시와 이동
- 날짜와 시간은 startsAt에 사용자 기기의 시간대를 적용해 표시한다. 날짜 경계와 서머타임에 해당하는 시각도 해당 시간대 규칙에 맞게 표시한다.
- 기기 시간대 변경 후 재표시하면 현재 시간대로 날짜·시간을 표시하며, 정렬과 Race.startsAt을 유지하고 추가 조회하지 않는다.
- 장소 누락은 “장소 정보 없음”으로 표시하며 다른 레이스는 정상 표시한다.
- 레이스 선택과 이동 상태는 View가 소유하고 선택한 sessionID에 해당하는 상세 화면으로 진입한다. 목록에서 드라이버 결과나 라디오를 미리 조회하지 않는다.

연도 선택, 페이지네이션, 새로고침과 상세 화면 자체 구현은 이 완료기준의 범위에 포함하지 않습니다.
